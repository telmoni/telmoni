title: "Sessions"
description: "A project's Sessions page: every session its agents took part in within the window, with its user, traces, errors, steps and tokens, and each session's own page — its runs replayed in metadata, never a message."
---

A **session** is the runs that share the session id the application gave
them: a chat, a thread, a support ticket worked over several runs — what
OpenTelemetry calls `gen_ai.conversation.id`. A project's **Sessions** page
lists every one seen in the window with the user it was with and what its
runs added up to, and each has a page of its own, where its runs are replayed
in order. Everything on both is metadata — which agent ran, how it ended, its
steps and tokens — and nothing on either is a message, in any
[content mode](/docs/api/ingest#what-is-dropped-at-the-door). A session here
is not a sign-in: those are listed under
[Account › Privacy](/docs/account/privacy#active-sessions).

## Naming the session

Name the session when you open a run — `session_id` in the
[SDKs](/docs/api/sdks) (`sessionId` in TypeScript, `SessionID` in Go),
`gen_ai.conversation.id` on the span — and every span
inside the run carries it. A run that names no session belongs to none; a
project whose runs name none sees the page say so, with the attribute to set.

## The list

| Column | What it is |
|---|---|
| Session | The session id, as the application set it; opens the session |
| User | The end user it was with, as stored: hashed under the project's own key; opens their traces |
| Traces | How many runs the session had in the window |
| Errors | How many of those had a span that failed |
| Steps | The steps those runs took, summed |
| Tokens | Their model calls' input and output tokens, summed; hover for the split |
| First seen | When the session's first run in the window started, in your time zone |
| Last seen | When its last run in the window ended |

**Sort** by any column by clicking its heading; the session last heard from
comes first. A second click turns the sort round. Ids and first seen sort the
alphabet's and the calendar's way; the most and the latest come first on the
others.

**The window** is the last day, week, 30 or 90 days, by the day each span
arrived. The page reads the spans within it — never the whole table — so a
session whose runs have all passed their retention is no longer listed. Up
to 100 sessions are shown, and the page says when the window holds more: show
up to 500, or narrow the window.

The sort and the window are in the page's URL, so a link holds the view.

## A session

A session's page sums it — its id in full, its user, how many runs it had and
how many had a span that failed, their steps and tokens, when the first
started and the last ended — and lists its runs in the order they started,
each with its agent, status, steps, tokens and duration, and each opening
[its trace](/docs/workspace/traces#a-trace). Up to 100 runs are shown, from
the same window as the list: show up to 500, or narrow the window.

A session id is the application's own text, up to 200 characters, so the
page's URL carries it encoded. A session none of the project's runs in the
window belonged to — one whose runs have passed their retention, or another
project's — says so, and leads back to the list.
