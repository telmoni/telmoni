An **evaluator** asks a model to judge what an agent did and give a
[score](/docs/monitoring/scores): a prompt, the score it gives, and the model
on one of the project's own [model connections](/docs/workspace/model-connections),
never a model of Telmoni's. A project's evaluators are on its **Evaluators**
page, under **Evaluation** in the project's rail; owners and admins make,
change and delete them, and everyone on the project reads them. A program does
the same under [`/v1/evaluators`](/docs/api/reference#get-v1evaluators): any
key with the `read` scope reads them, and one with `evaluate` beside it,
which an owner or admin mints, changes them, each change filed as the key's.

An evaluator reads the prompts and answers it judges, so it runs only on a
project that keeps [content](/docs/monitoring/content): on a project
that keeps none the page says so, and none is made.

## The prompt

A prompt is a system message, saying who the judge is and what it looks
for, then a user's message holding what is judged; an assistant's answer
after a user's message, and another user's message after it, is a worked
example. Each `{{variable}}` is filled from what is judged:

| Variable | What fills it |
|---|---|
| `{{input}}` | A run's input: its own span's input messages, else its first model call's |
| `{{output}}` | A run's output: its own span's output messages, else its last model call's |
| `{{metadata}}` | Its agent, status, duration, models, tokens, deployment and tags |
| `{{tool_calls}}` | Each tool it called, in order, with the arguments |
| `{{trajectory}}` | Each tool call with its arguments, result and status, in order |

A span fills the same four but the trajectory: its own input and output
— a tool call's arguments and result — its metadata, and the tool calls it
made or is. A session fills its own:

| Variable | What fills it |
|---|---|
| `{{messages}}` | Each run's input and output, in order, as the person's and the agent's messages |
| `{{exchanges}}` | Each run as a pair, the person's message and the agent's answer |
| `{{first_and_last}}` | The session's first prompt and its last answer |

Any evaluator may also name `{{examples}}`: the newest five corrections
members made of it ([Taught by people](#taught-by-people)).

A variable is filled with up to 60,000 characters of what it reads, and
says where the rest was cut. A draft is tried on a trace, so one naming a
session's variables, or `{{examples}}`, which a saved evaluator's
corrections fill, is not tried.

## The score

The score is a [score](/docs/monitoring/scores)'s name and type, each end
or category described for the model:

- **A number on a range**: its least and its most, and what each means.
- **Yes or no**: what yes means, and what no means.
- **Categories**: two to ten, each named and described, one or several at once.

The model is asked for JSON in the score's own form, with its reasoning
first where the evaluator asks for it; an answer outside that form, a
number off the range or a category it does not name, gives no score. The
reasoning becomes the score's [comment](/docs/monitoring/scores#a-scores-comment),
its first 4,000 characters, kept as the run's content is; a session's score
keeps none.

## Files

A prompt evaluator may send the files its variables name — the images,
PDFs and recordings a run's messages carried, as the project keeps them
([Content](/docs/monitoring/content)) — to the model as its provider's own
parts, beside the last user's message, when **Send the images, PDFs and
recordings** is ticked on its form. It is off unless ticked, since a model
that reads text alone refuses them.

| Provider | Takes |
|---|---|
| OpenAI | Images and PDFs, up to 20 MB each |
| Azure OpenAI, OpenAI-compatible endpoint | Images, up to 20 MB each |
| Anthropic | Images up to 5 MB, PDFs up to 32 MB |
| Amazon Bedrock | Images up to 3.75 MB, PDFs up to 4.5 MB |
| Google AI Studio, Google Vertex AI | Images, PDFs, and WAV, MP3, Ogg, FLAC and AAC recordings, up to 20 MB each |

An image is a PNG, JPEG, GIF or WebP. Up to five files are sent, 10 MiB
between them; a file past those or its provider's own limit, one no longer
kept, or one of a kind its provider takes none of stays out, never opened,
and the message says how many did. A try opens each file it sends as the
member's read, filed in the [audit log](/docs/workspace/audit-log) as the
trace's page does; an evaluation's are recorded on its row with the rest of
what it read. Neither sends the files a correction names, which are other
runs' ([Taught by people](#taught-by-people)), and a typed evaluator sends
none.

## The model

An evaluator judges with the project's default connection, or one it names,
and the connection's first model, or one it names, at the provider's own
temperature or one from 0 to 2. A typed evaluator judges on a System One
connection alone, and a prompt one on any other: saving or trying either
on the other kind's connection is refused, and the loop pauses it until its
connection, or the project's default, is one of its own. Saving asks the model once for an answer
in the score's form, and a model that cannot give one, or a connection the
provider refuses, saves nothing: the page shows why.

## Typed evaluators

A **typed** evaluator asks no model to write. It judges on a
[System One connection](/docs/workspace/model-connections) — TypeSafe's Jev,
or an open-weight model speaking its shape — with a **state** and one to
sixteen **questions**. The state holds what is judged and nothing of how to
judge it: the same variables a prompt's do, filled the same way, but never
`{{examples}}`. Each question has its own instructions and is its own score:

- **Yes or no**: a yes-or-no score, yes where the model gives yes more than
  even odds; what yes and no mean is optional.
- **Ordered levels**: two to ten, the lowest first, each described; a number
  from 0 to the highest level, the levels' probability-weighted value, so it
  may fall between two.
- **One of options**: two to 255, each named and optionally described; a
  category, the likeliest option.

One call answers every question of an evaluator on a target. Each score
carries its answer's probabilities, its confidence where the model gives
one (a yes or no gives none) and the model version that answered, shown
beside each answer when a draft is tried. A state longer than the model's
context leaves its longest question beside it, about 96,000 characters, is
cut to fit and its evaluation marked as cut; an answer outside a question's
levels or options gives no score.

Jev's calls are priced at the project's own price for the provider
`typesafe` and its model's name, set under **Model prices** on the
project's **Settings** page, since the price table lists none; an
open-weight endpoint's are unpriced, as an OpenAI-compatible endpoint's
are.

A typed evaluator cannot abstain and gives no reasons, so its scores carry
no comment, and it takes no temperature. An open question, or one whose
answer needs written reasons, stays a prompt evaluator's.

## Templates

**New evaluator** starts from a blank prompt, a blank typed evaluator or a
template, copied, never linked, so a change to one changes nothing else:

| Group | Templates |
|---|---|
| Quality | Hallucination, Correctness, Answer relevance, Conciseness, Helpfulness |
| Safety | Toxicity, Bias |
| Security | PII leakage, Prompt injection |
| Conversation | Task completion, User satisfaction, Tone, Perceived error |
| Agents | Tool selection, Plan adherence, Trajectory accuracy |
| Typed | Tool selection, Task completion, Scope adherence, Groundedness, Prompt injection, PII in the answer |

## Trying one

Before it is saved, an evaluator is tried on one of the project's traces,
by its run id: the page shows the score and the reasoning the model gave,
or each typed question's score and its probabilities, the tokens it used,
and the prompt or the state exactly as it was sent. A try reads the
trace's content as its page does, so the read is filed in the
[audit log](/docs/workspace/audit-log) as the member's, and it keeps
nothing.

## Rules

A **rule** says what its evaluators judge, under **Rules** on the same
page; several evaluators share one, and owners and admins make, change and
delete them:

- **Runs**, each once its own span has arrived and a minute has passed.
- **Spans** of one kind — model calls, tool calls, steps or other spans —
  and of one name where the rule names one.
- **Sessions**, each once quiet for the project's idle time, ten minutes
  unless an owner or admin sets two to 1,440 under the rules.

A rule takes a saved view's filters from the [trace list](/docs/monitoring/traces),
never its sort or window, and judges a share of what they admit, from
0.1% to all of it, chosen by a hash of each target's id so the same target
is always chosen alike. Each variable may be narrowed by a
[JSON Pointer](https://datatracker.ietf.org/doc/html/rfc6901), `/0/content`
for the first message's text: a variable that holds no JSON, or a pointer
that finds nothing, is sent empty. Before a rule is saved, **Preview the
last 7 days** counts what it would have found and judged, and what each
evaluator would have cost at its model's price, where the
[price table](/docs/monitoring/dashboards) holds one; a span rule's count is
the spans of its kind and name in the runs its filters admit, as its
evaluations find them. A plan holds as many rules as it holds
[alerts](/docs/monitoring/alerts), across its projects, and a rule off judges nothing.

## Evaluations

Each minute Telmoni looks over every rule's newest targets and writes one
**evaluation** for each evaluator and target, whichever rule found it, then
judges each, five at a time an organization:

- **Done**: the model answered in the score's form, and its score is on
  the target, its source the evaluator and its version. Each evaluation is
  also a trace of its own in the project — a run and its one model call,
  the prompt sent and the answer, with its tokens, latency and cost — under
  the environment `telmoni-evaluator`, which the trace list leaves out
  unless its environment filter names it, and which counts against the
  plan's spans and its spend as any call does. It holds a copy of what it
  read, so deleting the trace it judged, or erasing that trace's end user,
  deletes it too.
- **Delayed**: the provider's rate limit holds, until its `Retry-After` or
  a backoff from a minute to an hour; or the evaluator's weekly spend
  limit, set on its form, is reached, until Monday 00:00 UTC.
- **Pending**: waiting, or paused — while the project keeps no content,
  while its connection is deleted, and while the provider refuses its key,
  which pauses every evaluator on that connection, until it is saved
  again with a key the provider takes, and tells the organization's owner
  and admins once in the organization's feed, and its owner by mail.
- **Failed**: the answer was outside the score's form, the target is no
  longer kept, or the provider failed five times; the reason is shown.

An evaluator reads only what its project keeps, and sends it only to its
connection's provider; a field an SDK cut to fit an export is judged as
cut, and the evaluation says so. Its reads are not filed in the audit log,
which a machine's load would crowd: each evaluation's row is their record,
naming the evaluator, the target, the time and the provider, kept as long
as what it read. **Evaluations** on an evaluator's row opens its newest,
each linked to what it judged and to its own trace, its counts, and what it
spent since Monday.

## Taught by people

A member's score of a run or a span that an evaluator scored, under the same
name, is a correction of it, as LangSmith's few-shot evaluators learn: kept
with the input and output the evaluator read, up to 2,000 characters of each,
what it said and what the member said instead. A correction is content, kept
only where the project keeps content and holds room for it, sealed with the
run's own content, so it goes with the run, an end user's erasure and the
project's retention; scoring again replaces it, taking the score back takes
it back, and deleting the evaluator deletes every one it was taught. A
session's score teaches nothing, since no run of the session holds it. An
evaluator whose prompt names `{{examples}}` is given its newest five, each
read recorded on its evaluation as the rest of what it reads is; its
evaluation's own trace keeps only how many, since each is another run's
content, so a correction goes with its own run and never with another's.

## Agreement with members

An evaluator's page reads how far it agrees with the project's members over
the last 30 days: each of its scores beside a member's of the same name on the
same run, span or session, given in the window, as Langfuse's score analytics
read it. A yes or no and a category show the share of pairs agreeing, Cohen's
kappa — agreement past what chance alone would give, none where every pair
gave one answer — and the confusion matrix, its answers by row and its
members' by column; a number shows its mean difference from its members'.
A pair of two types is left out. The same reading answers
`GET /internal/v1/telemetry/evaluators/{id}/agreement?days=`, 1 to 360 days.

## Versions

Every save is a new version under the evaluator's same id, and each score an
evaluator gives names the version that gave it; a target judged once is not
judged again by a later version. The page shows the newest and opens every
version. Each version saved and each evaluator deleted is
filed in the audit log by its score's name and type, never its prompt, and
deleting one takes every version, leaving the scores it gave. A project
holds up to 50 evaluators.
