Telmoni's open-source platform is [`telmoni/telmoni`](https://github.com/telmoni/telmoni) on GitHub, the four SDKs under `sdk/` and these pages with it; the CLI is [`telmoni/telmoni-cli`](https://github.com/telmoni/telmoni-cli). Thanks for helping build it. Everyone taking part follows the [Code of Conduct](/docs/contributing/code-of-conduct), and the [AI policy](/docs/contributing/ai-policy) says how AI tools fit in.

## The repositories

- [`telmoni/telmoni`](https://github.com/telmoni/telmoni), the platform, the four SDKs (`sdk/`) and these pages (`web/content/docs`), which its console serves at `/docs`. [Developing it](/docs/contributing/developing#the-platform) takes two commands; [`ARCHITECTURE.md`](https://github.com/telmoni/telmoni/blob/main/ARCHITECTURE.md) explains how it is built on one page: the place to read before changing anything structural. [The docs](/docs/contributing/developing#the-docs) says how a page is wired, and every claim on one is checked against the code first. `make ci` is the gate.
- [`telmoni/telmoni-cli`](https://github.com/telmoni/telmoni-cli), the CLI. [Developing it](/docs/contributing/developing#the-cli); its [`ARCHITECTURE.md`](https://github.com/telmoni/telmoni-cli/blob/main/ARCHITECTURE.md) explains how it is built on one page. `cargo xtask ci` is the gate.
- [`telmoni/claude-code-observability-plugin`](https://github.com/telmoni/claude-code-observability-plugin), [`telmoni/codex-observability-plugin`](https://github.com/telmoni/codex-observability-plugin) and [`telmoni/antigravity-observability-plugin`](https://github.com/telmoni/antigravity-observability-plugin), the Claude Code, Codex and Antigravity plugins. Each one's `ARCHITECTURE.md` explains how it is built and tested; `npm run verify` and `npm run validate` are the gate.

## Before you start

Open an issue first for a new feature, a schema change or anything architectural, so the shape is agreed before the work. A bug fix or a small improvement can go straight to a pull request.

## How the platform's code is shaped

- **Rust owns the rules.** Business logic, queries, authorization, tenancy and the audit log live in `crates/`; the console in `web/` is a thin proxy and holds none of them.
- **Never log a secret or personal data**, at any level. Secrets are held in `Redacted` and read on purpose.
- **Before the platform's first release** there are no migration paths: a schema change edits the module's existing migration, and `make db-reset` rebuilds the local database. After a change to the wire contract, `make contract` regenerates it.

## Before you push

Run the repository's gate, which is what its CI runs: `make ci` in the platform (formatting, clippy, rustdoc, the Rust tests against a local Postgres and ClickHouse, the console's typecheck, lint, dead-code check, tests and build, the SDK suites, the chart and the compose file rendered, and the dependency and spelling checks), `cargo xtask ci` in the CLI, and `npm run verify` and `npm run validate` in each plugin, CI linting the CLI's and the plugins' workflows with actionlint beside them. The Antigravity plugin's CI runs no `validate`, for want of a pinned `agy` to install, so run it yourself before you push. A pull request is reviewed once its gate passes.

## Commits and pull requests

- Keep a pull request to one change.
- Commits follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`).
- Every commit is signed off by its author: `git commit -s` adds `Signed-off-by: Your Name <you@example.com>` from git's `user.name` and `user.email`, certifying the [Developer Certificate of Origin](https://developercertificate.org/), that you may submit the change under the project's Apache-2.0 licence, as its section 5 provides. A pull request with a commit not signed off is sent back to be signed, and the merge commit is signed off too: a maintainer merges from a clone with `git merge --no-ff --signoff` and pushes, never from GitHub's merge button, whose commit carries none.
- Understand every line you submit, whatever tools helped you write it ([AI policy](/docs/contributing/ai-policy)).

## Security

A suspected vulnerability is never a public issue: see [reporting a vulnerability](https://telmoni.com/docs/legal/security#reporting-a-vulnerability), which is the security policy of every Telmoni repository.
