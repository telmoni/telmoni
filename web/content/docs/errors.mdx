Telmoni reports API and console errors using Problem Details for HTTP APIs
([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457), sent as
`application/problem+json`). Each problem document carries a stable URI `type`
your code can branch on.

## The shape of an error

```json
{
  "type": "/errors/authz/insufficient-role",
  "title": "insufficient role",
  "status": 403,
  "detail": "required admin, have member"
}
```

- `type` is a URI that identifies the problem kind. It never changes between
  deployments.
- `title` is a short, human-readable summary of the problem type.
- `status` is the HTTP status code, repeated inside the body.
- `detail` is human-readable and explains this specific occurrence. Some
  errors carry none, so treat it as optional.
- Additional keys may appear on specific error types, as noted below.

## Error types

| Type | Status | Means | Extra fields |
|---|---|---|---|
| `/errors/auth/unauthenticated` | 401 | You are not signed in, your session was ended, or your account is being deleted; on the CLI's lanes, also a request that carried no credential. | |
| `/errors/auth/token-expired` | 401 | Your session has expired. Sign in again. | |
| `/errors/auth/invalid-token` | 401 | The credential sent is not valid, or the [API](/docs/api/reference) got none. | |
| `/errors/auth/service-credential-rejected` | 401 | One of Telmoni's services refused another's credential. This is Telmoni's fault, not yours. The API and the CLI's lanes answer it as a `503` instead (see below). | |
| `/errors/auth/identity-unavailable` | 503 | Telmoni could not check who you are right now, because the identity provider's keys or its own identity service could not be reached. Try again shortly. | |
| `/errors/auth/not-found` | 404 | The thing you named does not exist, or is not yours to see. `detail` says what kind of thing. | |
| `/errors/auth/bad-request` | 400 | A value was not acceptable, such as a malformed email address. `detail` says which. | |
| `/errors/auth/bad-url` | 400 | The URL asked for an organization is not one it may go by: not lowercase letters and digits in words joined by single hyphens, longer than 48 characters, a word the console's own pages use, or a word no URL may hold. `detail` says which, without repeating a word no URL may hold. A URL another organization holds is a `409` instead. | |
| `/errors/auth/conflict` | 409 | It already exists, conflicts with something that does, or something is not in the state the request needs, such as deleting your account while you own an organization other people are in. `detail` says what. | |
| `/errors/authz/forbidden` | 403 | You are signed in and this is not allowed. `detail` says why. | |
| `/errors/authz/insufficient-role` | 403 | Your role does not allow this. `detail` names the least role that would, such as `required admin, have member`. | |
| `/errors/tenant/cross-tenant-denied` | 403 | Reserved for a request that reaches outside the organization or project it may act in; no lane returns it. | |
| `/errors/bad-request` | 400 | The request body did not parse or failed validation. `detail` names the field. | |
| `/errors/payload-too-large` | 413 | The request body is larger than this route accepts, such as a body over 8 KiB sent to the CLI's lanes. | |
| `/errors/incompatible-client` | 426 | Reserved for a client older than the oldest version Telmoni supports; no lane checks a client's version, so none returns it. | |
| `/errors/tenant/rate-limited` | 429 | Too many requests. Wait and try again. A `Retry-After` header carries the same number of seconds. | `retry_after_secs` |
| `/errors/tenant/feature-off` | 503 | This feature is switched off, for your organization or for the whole deployment. `detail` says which in a sentence. | `flag`, `retry_after_secs` |
| `/errors/mail/delivery-failed` | 502 | An email this request depended on, such as a confirmation code, could not be sent. | |
| `/errors/connectors/key-unavailable` | 502 | The key that seals connector secrets could not be reached, so a connector could not be set up or its secret rotated. Nothing was changed; try again shortly. | |
| `/errors/internal/database` | 500 | Telmoni's database failed. | |
| `/errors/internal/unknown` | 500 | Something else on Telmoni's side failed. | |
| `/errors/agent/disabled` | 503 | The operator of this deployment has not configured the console agent. | |
| `/errors/agent/model-unavailable` | 502 | The model or embeddings service behind the console agent did not answer. Nothing was changed; try again shortly. | |
| `/errors/agent/rate-limited` | 429 | You have asked the console agent as many questions as this hour allows. | `retry_after_secs` |

`feature-off` answers `503` with a retry hint, not `404`, on purpose: the route
exists and the switch is Telmoni's, so a program should wait and retry rather
than conclude the route is gone.

## Answers whose type is not in the table

Some answers are problem documents whose type the table above does not list,
because they come from the console in front of the server rather than from the
server itself.

**A method a lane does not take** is `405` with an `Allow` header. The
[API](/docs/api/reference) takes `GET` and `HEAD` (`OPTIONS` alone answers `204`,
with `Allow: GET, HEAD, OPTIONS`). The CLI's lanes take `POST`: a `GET` or
`DELETE` to one answers with `Allow: POST` and the detail "this lane takes
POST", and a `PUT` or `PATCH` gets a bare `405` with no body:

```json
{
  "type": "/errors/method-not-allowed",
  "title": "method not allowed",
  "status": 405,
  "detail": "this lane takes GET, HEAD, OPTIONS"
}
```

**A server that did not answer** is `503`; wait and try again. The API and the
CLI's lanes answer the same type when the server refused the console's own
credential, with the detail "the platform failed on its own side; try again
shortly"; on a self-hosted deployment, one that persists means the console's
`SERVICE_SECRET` no longer matches the server's:

```json
{
  "type": "/errors/upstream-unavailable",
  "title": "upstream unavailable",
  "status": 503,
  "detail": "the server did not answer; try again shortly"
}
```

**A path under `/cli` that none of the CLI's lanes serves** is `404`:

```json
{
  "type": "/errors/not-found",
  "title": "not found",
  "status": 404,
  "detail": "no such lane"
}
```

On `/v1`, a server that cannot reach its database while it checks the key
answers `503` with `/errors/auth/identity-unavailable`, from the table; anywhere
else a database failure is `500` with `/errors/internal/database`. A path under
`/v1` that no lane serves answers `404` with `/errors/auth/not-found`.
