title: "Content"
description: "What a run said, kept in full when both locks are on: the project's content mode and the SDK's capture switch. What is kept — messages, tool payloads, images and files, failures and metadata — where it is read and recorded, and how long it stays."
---

**Content** is what a person or a model wrote during a run: the prompts and
completions of its model calls, the inputs and outputs of its tool calls, the
images and files a message carried, a failure's message and stack trace, and
any metadata your code attaches beyond what the
[field inventory](/docs/api/field-inventory) names. Everything else a span
carries is **metadata** — its name, timings, status, tokens, model and tool
names, tags, a user id, an error's type — which Telmoni keeps on every project,
whatever its mode. Prompts stay in your process unless you turn content on.

## The two locks

Content leaves your code only when both of these are on, and with either off
the span is sent and kept without it:

1. **Your switch, in the SDK.** A client sends content only when it is built
   with `capture_content` on (`captureContent` in TypeScript, `CaptureContent`
   in Go), or from the environment with `TELMONI_CAPTURE_CONTENT=1`
   ([SDKs](/docs/api/sdks#content)). Each coding-agent plugin has the same
   switch beside its key ([Coding agents](/docs/api/coding-agents#a-turns-conversation)),
   and each framework's instrumentation its own ([Frameworks](/docs/api/frameworks#content)).
2. **The project's content mode**, `off` until the organization's Owner turns
   it `on` on the project's **Settings** page, with a code mailed to them
   ([A project's content mode](/docs/workspace/organizations-and-projects#a-projects-content-mode)).
   The SDK asks the server for the mode before the first content it would
   send, and learns it again from every answer. Ingest reads it on every
   export too, and drops content at the door on a project left `off`
   ([Ingest](/docs/api/ingest#what-is-dropped-at-the-door)).

## Masking what should never leave

With both locks on, content is kept as your code sends it. To keep part of it
home — a card number, an email address, a secret pasted into a prompt — give
the SDK a mask: a function of yours that each content field passes through
before it leaves the process, answering what to send instead, or nothing to
send the span without that field
([SDKs](/docs/api/sdks#masking-content)). It sees the content the SDK records —
messages, tool payloads, failures and events — never a span's name, its tags or
a user id, which are metadata kept on every project, nor an attribute your code
sets on a span itself, which is kept below as metadata content: keep a person
out of those in your own code.

After your mask, the SDK's scrubbers replace what has a shape of its own:
secrets, on wherever content is sent, and personal data, where you turn it on,
each by a marker such as `[secret: aws_key]` or `[pii: email]`, counted on the
run's page ([SDKs](/docs/api/sdks#scrubbing-secrets-and-personal-data)). No
pattern finds a name, a street address or text inside an image: what only your
application knows is the mask's to keep home.

## What is kept

On a project that keeps content, ingest keeps each piece whole, past the 1,024
characters an attribute is otherwise held to, sealed under a key of the
project's own, in Postgres alone, never in the span store:

- **Messages**: a model call's system instructions, the tools it was offered,
  and its input and output messages; and a run's own input and output, its
  turn of a conversation.
- **Tool payloads**: a tool call's arguments and result; a retrieval's query
  and documents.
- **Images and files**: a part of a message holding a file's bytes is lifted
  out by the SDK before export and sent once, by its SHA-256, to
  `PUT /v1/media/{sha256}`, up to 5 MiB a file, and the message names it
  ([SDKs](/docs/api/sdks#content)). The trace page draws a PNG, JPEG, GIF or
  WebP image, plays audio, and offers any other file as a download.
- **Failures**: a failed span's status message, its `exception` event with
  the stack trace, and every event your code adds to a span, a
  [score](/docs/monitoring/scores)'s own keys apart, which are metadata. With
  either lock off, a failure keeps its `error.type` and its error status alone.
- **Metadata**: any text, list or map attribute of a span the field inventory
  does not name. One on the resource is dropped in every mode, since a
  resource is copied onto every span of its export.

A field an SDK cut to fit an export is not kept, and the trace says so.

## Where it is read

- **The trace's page** and its view beside the list show each span's content
  in full ([Traces](/docs/monitoring/traces#content)).
- **A download** of the trace list carries every run's content.
- **The API** answers a trace's content with `content=true`
  ([API reference](/docs/api/reference#get-v1tracesrun_id)).

Each read is recorded in the organization's
[audit log](/docs/workspace/audit-log) as `viewed` before the content is sent,
naming the traces read and never what they hold, so the project's
**Audit log** lists who read it.
The console agent reads none of it, in any mode.

## How long it stays

Content is kept as long as its span, the project's retention
([Data retention](/docs/workspace/data-retention)), and deleted with it, with
its trace, with the project, and by an end user's erasure
([Data deletion](/docs/workspace/data-deletion)). Turning the mode back to
`off` takes in no more, and keeps what was sent until its retention ends,
unless the Owner also ticks **Also delete what this project kept**, which
deletes its key at once and its rows right after
([Deleting a project's content](/docs/workspace/data-deletion#deleting-a-projects-content)).
On a deployment that sells plans, an organization past its plan's content
ceiling keeps each new span's metadata alone, each field named
`content_full`, and keeps no file uploaded apart
([Ingest](/docs/api/ingest)); a self-hosted installation has no plans and no
ceiling.
