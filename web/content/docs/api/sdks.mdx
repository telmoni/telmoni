---
title: "Client SDKs"
description: "The Telmoni SDKs for Python, TypeScript / JavaScript, Go and Rust: an agent's traces, steps, model calls, tool calls and retrievals as OpenTelemetry spans, sent to Telmoni and nowhere else."
---

The SDKs record an agent's **traces**, and the **steps**, **model calls**,
**tool calls** and **retrievals** inside each, as OpenTelemetry spans, and send them to
[ingest](/docs/api/ingest), and, where content is sent, the images and files
their messages carry to the platform beside them ([content](#content)). Each one runs a tracer provider of its own beside
whatever OpenTelemetry your application already has, sends nothing outside a
trace, and takes prompts, completions and tool payloads off every span before it
leaves the process unless you ask and the project's content mode allows.

| Language | Package | Requires | Source |
|---|---|---|---|
| **Python** | `telmoni` | Python 3.10 or later | [`sdk/python`](https://github.com/telmoni/telmoni/tree/main/sdk/python) |
| **TypeScript / JavaScript** | `telmoni` | Node.js 18 from 18.19, or 20.6 or later | [`sdk/typescript`](https://github.com/telmoni/telmoni/tree/main/sdk/typescript) |
| **Go** | `github.com/telmoni/telmoni/sdk/go` | Go 1.26.10 or later | [`sdk/go`](https://github.com/telmoni/telmoni/tree/main/sdk/go) |
| **Rust** | `telmoni` | Rust 1.88 or later | [`sdk/rust`](https://github.com/telmoni/telmoni/tree/main/sdk/rust) |

Their source is the platform's repository,
[`telmoni/telmoni`](https://github.com/telmoni/telmoni), which holds them
beside the ingest they send to, and each installs with its language's own
tool, below. Each is built on its language's OpenTelemetry SDK and sends with
the language's own HTTP client, Rust with reqwest. Python, TypeScript and Go
carry nothing else; Rust also carries serde, serde_json, tracing, uuid, ring and base64.

## A trace

A trace is one execution of an agent: a trace of its own, whose id is its
OpenTelemetry trace id, 32 hex digits. Open one around the agent's work, and
inside it open a step for each unit of work, a model call around each call to
a model, a tool call around each tool, and a [retrieval](#a-retrieval)
around each search of a vector store or a memory. The SDK sends each span when
it ends. Set `TELMONI_API_KEY` to a [project API key](/docs/api/api-keys)
holding the **ingest** scope.

<Tabs items={['Python', 'TypeScript', 'Go', 'Rust']}>
  <Tab value="Python">
    ```python
    from telmoni import Telmoni, Usage

    telmoni = Telmoni.from_env()


    @telmoni.trace("support-bot")
    def answer(question: str) -> str:
        with telmoni.step("plan"):
            with telmoni.model_call(
                "gpt-4o-mini", provider="openai", prompt="support-reply", prompt_version="3"
            ) as call:
                reply = ask_the_model(question)  # your provider's call
                call.answered(
                    response_model=reply.model,
                    usage=Usage(input_tokens=reply.usage.input, output_tokens=reply.usage.output),
                )
        with telmoni.tool_call("search"):
            results = search(reply.query)  # an exception marks the call failed
        return reply.text


    with telmoni.trace(
        "support-bot",
        user_id="user_42",
        session_id="conv_7",
        tags={"env": "prod"},
    ) as trace:
        ...
    ```

    Each of `trace`, `step`, `model_call` and `tool_call` is a context manager,
    an `async with`, and a decorator; on a generator, sync or async, the
    decorator's span covers its iteration. An exception that escapes one
    marks the span failed with the exception's class, records its message
    and stack trace as [content](#content), and is raised again; a
    `KeyboardInterrupt` or `asyncio.CancelledError`, or a generator closed
    before its end, marks it cancelled.
    `fail("TimeoutError")` and `cancel()` do the same by hand.
    `trace` raises `ValueError` for a blank agent name or a cap that is no cap
    ([the guard](#the-guard)). A token
    count is read from a number or its text, its fraction cut, and `Usage`'s
    `cost` is what the call cost in US dollars, where your provider reports
    it; of what Telmoni would refuse, these are left off with one warning: a
    token count below 0 or past 64 bits, a cost below 0, not finite, or text,
    a tag whose key is not 1 to 64 characters or whose value is past 256, and
    the tags past the first 32 kept; an empty user, session, provider or
    response model is left off as unset. A usage handed to `answered` that is
    no `Usage`, your provider's own usage object say, is taken as none, with
    one warning: copy its counts into a `Usage`. A name, model, provider, prompt, prompt version, user, session, response model or error
    type that is no string goes as its text with one warning, as does a tag
    that is no string, finite number or bool; an exception or an
    exception's class handed to `fail()` goes as the class's name, an
    exception's message and stack trace recorded as content. Past Telmoni's
    caps, counted in characters, a name, the agent, a model, a provider, a response model or an error type is cut to its cap — a
    step's or a tool's name to 145, the rest to 128 — and a user past 128 or a
    session past 200 is left off, since cut it would name another; a step named
    nothing goes as `step`, a model call with no model is named by its operation
    alone, and one of an operation ingest reads as no model call, any but
    `chat`, `generate_content`, `text_completion` and `embeddings`, goes as `chat`; each with one warning.
    A blank `prompt` or `prompt_version` is none, as an empty provider is; one
    past 1,024 characters is left off, never cut, since cut it would name
    another, and so is a version whose prompt is none or was left off, each
    with one warning.

    ```go
    	log.Fatal(err)

    ctx, trace := client.Trace(ctx, "support-bot", telmoni.TraceOptions{
    ```

Flush before a short-lived process exits (`flush()` / `flush()` / `Flush(ctx)`
/ `flush()`), or shut the client down, which flushes first. A long-lived one
needs no flush while it runs, but shuts the client down as it stops: a deploy
or a restart stops it with a signal, which drains nothing unless its handler
does. A process that ends of itself is drained for you, for at most a
shutdown's wait: Python's as the interpreter or a multiprocessing child exits,
Rust's as its last clone of the client drops and TypeScript's as Node's event
loop empties; none on a forced exit (`os._exit`, `process.exit()`,
`std::process::exit`). Go's drains only through `Shutdown`, so defer it. A
pool that terminates its workers, as `with Pool(...)` does as it closes, stops
them with a signal too, so a task run there flushes before it returns.

### Token counts

Input includes tokens read from and written to the provider's cache. Output
includes reasoning tokens. Set the reasoning subset where the provider reports it:

| SDK | Usage field |
|---|---|
| Python | `Usage(reasoning_output_tokens=...)` |
| TypeScript | `usage.reasoningOutputTokens` |
| Go | `Usage.ReasoningOutputTokens` |
| Rust | `Usage::reasoning_output_tokens` |

OpenAI's `reasoning_tokens` is already included in `completion_tokens`; copy
both counts without adding them. Gemini reports `thoughtsTokenCount` apart
from `candidatesTokenCount`: set output to candidates plus thoughts and
reasoning to thoughts. Anthropic reports no separate reasoning count.
Missing reasoning is stored as zero. These are counts alone, never reasoning text,
and remain metadata with content off. Reasoning is priced once, inside output.
Each count last supplied wins; a partial update preserves the other counts.
Go supplies all five counts each time its `Usage` is supplied, including zero.

### A retrieval

A search of a vector store or a memory is a call of its own: open a retrieval
around it, named by the source it searched, and hand it what came back. The
query and the documents are [content](#content), sent only when you ask and the
project's mode allows; how many results it asked for (`top_k`) and how many
came back are metadata, sent in every mode, the second counted from the list
you hand over before anything leaves the process. Telmoni keeps it as a
retrieval, named by its source, which an [alert](/docs/monitoring/alerts)
counts, times and fails as it does tool calls, by source.

<Tabs items={['Python', 'TypeScript', 'Go', 'Rust']}>
  <Tab value="Python">
    ```python
    with telmoni.retrieval("kb-articles", query=question, top_k=5) as found:
        found.returned(index.search(question, k=5))  # your vector store's search

    with telmoni.retrieval("customer-preferences", top_k=3, memory=True) as remembered:
        remembered.returned(memories.search(question, limit=3))
    ```

    `retrieval` is a context manager, an `async with` and a decorator, as
    `tool_call` is, on the client or on a trace; `returned` takes a list or a
    tuple.
  </Tab>
  <Tab value="TypeScript">
    ```typescript
    await trace.retrieval('kb-articles', { query: question, topK: 5 }, async (found) => {
      found.returned(await index.search(question, 5)); // your vector store's search
    });
    await trace.retrieval('customer-preferences', { topK: 3, memory: true }, async (remembered) => {
      remembered.returned(await memories.search(question, 3));
    });
    ```

    `retrieval` opens on a trace or a step, as `toolCall` does; `returned` takes
    an array.
  </Tab>
  <Tab value="Go">
    ```go
    _, found := trace.Retrieval(ctx, "kb-articles", telmoni.RetrievalOptions{Query: question, TopK: 5})
    found.Returned(index.Search(question, 5)) // your vector store's search
    found.End()
    ```

    `Returned` takes a slice or an array, never of bytes, so a `[]byte` or a
    `json.RawMessage` is refused; a nil slice counts as none came back. A
    `TopK` of 0 is none.
  </Tab>
  <Tab value="Rust">
    ```rust
    use telmoni::RetrievalOptions;

    let found = trace.retrieval(
        "kb-articles",
        RetrievalOptions { query: Some(question.into()), top_k: Some(5), ..RetrievalOptions::default() },
    )?;
    found.returned(&index.search(question, 5)?); // your vector store's search: a Vec<serde_json::Value>
    drop(found);
    ```

    `retrieval_with` and `try_retrieval_with` are its closure forms, as a tool
    call's are.
  </Tab>
</Tabs>

With `memory` on, the span is a search of a memory store, `search_memory`,
its source `gen_ai.memory.store.id` and how many records came back
`gen_ai.memory.record.count`; otherwise it is `retrieval <source>`, its source
`gen_ai.data_source.id` and the count `telmoni.retrieval.returned`. A source
names a store, never a person: it is kept as metadata in every mode and in the
hourly totals for thirteen months, so a memory kept for each of your users
names the user in the trace's `user_id`. A source past 145 characters is cut to
145, a blank one sends the span named by its operation alone, and a `top_k`,
read as a token count is, is left off below 0, each with one warning. Anything
handed to `returned` but a list is refused whole, with one warning, and the
last list handed over wins: its documents and its count are set together.

## A trace recorded after it ended

A job that keeps its own log, or a hook that runs once the work it reports is
over, hands the finished trace over whole, as data: its id, 32 hex digits you
give and keep with the log; its agent, user, session and tags; the messages it was
asked and answered with, which are [content](#content); its start and end and
how it ended; and its steps and calls, each with its own times. A step holds
the calls made inside it, and steps of its own, a subagent's own subagents say,
up to 16 deep, each sent under the step that holds it. Each step and call may
carry its own content too: a model call the messages it was sent and those it
produced, a tool call its arguments and its result, and a step the messages it
was asked and answered with, a subagent's task and its answer say. A model call
may also name its reasoning effort, how hard its model was asked to reason, as
its provider names it, which is no content and is sent whatever the mode. A
record the export queue has no room for is refused
whole, before anything is queued: flush, or wait, and record it again. A
record of more spans than the queue holds, 2,048 unless you
[raise it](#answers-and-warnings), is never taken, and the refusal says so. One
made once the client is shut down is refused too, never taken as sent. Its
times are read as the clock of the process that sends it: where that clock is
a time zone or a date out, [ingest moves the record](/docs/api/ingest#what-is-kept)
by as much, so time a record by the clock that sends it.

<Tabs items={['Python', 'TypeScript', 'Go', 'Rust']}>
  <Tab value="Python">
    ```python
    from datetime import datetime, timezone

    from telmoni import ModelCallRecord, ToolCallRecord, TraceRecord, Usage

    at = lambda s: datetime(2026, 10, 12, 9, 0, s, tzinfo=timezone.utc)

    telmoni.record_trace(
        TraceRecord(
            trace_id="3d6f8a1c5b2e4f7a9c0d8e1f2a3b4c5d",
            agent="nightly-triage",
            session_id="conv_7",
            start=at(0),
            end=at(9),
            inside=[
                ModelCallRecord(
                    model="gpt-4o-mini", provider="openai", start=at(0), end=at(2),
                    usage=Usage(input_tokens=1200, output_tokens=85),
                ),
                ToolCallRecord(name="search", start=at(2), end=at(3), error_type="TimeoutError"),
            ],
        )
    )
    telmoni.flush()
    ```

    Times carry their timezone. A `StepRecord`'s `calls` hold steps as well as
    calls, and a `ModelCallRecord` takes `input_messages` and
    `reasoning_effort`. A blank agent, a trace id that is not 32 hex digits
    or is all zeros, a time without its
    timezone or outside what Telmoni reads (after the Unix epoch, and less than
    2^64 nanoseconds after it, in July 2554), an empty step's name or model,
    text longer than Telmoni keeps (a step's or a tool's name past 145
    characters, the agent, a model, a provider, a user or an error type past
    128, a session past 200, or a reasoning effort past 1,024), a step nested
    past 16 deep, or a span that ends before it starts raises `ValueError`. A field of the wrong type raises
    `TypeError` — a time that is no `datetime`, an item of another class,
    `inside` or `calls` that is no sequence (a list or a tuple) — save a token
    count, read as a whole number where it can be and else left off with one
    warning, and an `operation` of `None`, a chat. Either way, nothing is sent.
  </Tab>

    wrong type — a time that is not one, an item of no known `type`, `inside`

    token count, read as a whole number where it can be and else left off with
    one warning. A time outside what Telmoni reads (after the Unix epoch, and
    less than 2^64 nanoseconds after it, in July 2554), text longer than
    Telmoni keeps (a step's or a tool's name past 145 characters, the agent, a
    model, a provider, a user or an error type past 128, a session past 200, or
    a reasoning effort past 1,024, counted in characters), a step nested past
    16 deep, or a span that ends before it starts throws a `RangeError`. Either way, nothing is sent.
  </Tab>
  <Tab value="Go">
    ```go
    start := time.Date(2026, 10, 12, 9, 0, 0, 0, time.UTC)
    ```

in the record, and a record travels in bodies of its own, so the same record
sent again is the same bytes, whatever else the client is sending, which
Telmoni, where it reaches its Redis, answers within the hour as it answered
the first, storing nothing twice: give a trace the same id each time you send
it. A record's content, the agent's and each step's and call's, leaves under
the same two locks as a live trace's.
The [Claude Code, Codex and Antigravity plugins](/docs/api/coding-agents) are built on it.

## Scores

A [score](/docs/monitoring/scores) judges a trace, one of its spans or a
session: a name, 1 to 64 characters, and a number, a yes or no, or a category
of up to 64 characters. A number may name its range, which it must fall
within, and any score the version of what scored, up to 64 characters. A
score is metadata, sent in every content mode and never handed to your
[mask](#masking-content).

On a handle still open — a trace, a step, a model call, a tool call or a retrieval — `score`
puts it on that span, as OpenTelemetry's evaluation event, and it leaves with
the span. Once the span has ended, a person's feedback on an answer say, or
for a session, the client's `score` names what it scores — a trace by its id, a
span by its trace's id and the handle's span id, or a session — and sends it to
[`POST /v1/scores`](/docs/api/reference#post-v1scores) with the next export,
under the same key; a flush or a shutdown sends it as it sends the spans
queued, and a retry keeps it once. A record's trace, steps and calls take their
scores too, each sent at its span's end.

<Tabs items={['Python', 'TypeScript', 'Go', 'Rust']}>
  <Tab value="Python">
    ```python
    with telmoni.trace("support-bot", session_id="conv_7") as trace:
        with telmoni.model_call("gpt-4o-mini", provider="openai") as call:
            ...
            call.score("grounded", True)
        trace.score("relevance", 0.8, range=(0, 1), version="judge-2")
        trace_id, span_id = trace.trace_id, call.span_id

    # Later, once the person answered:
    telmoni.score("thumbs", True, trace_id=trace_id)
    telmoni.score("outcome", "resolved", session_id="conv_7")
    ```

    `value` is a `bool`, a yes or no; an `int` or a `float`, a number; or a
    `str`, a category. A record's trace, steps and calls take
    `scores=[{"name": "thumbs", "value": True}]`.
  </Tab>
  <Tab value="TypeScript">
    ```ts
    await telmoni.trace('support-bot', { sessionId: 'conv_7' }, async (trace) => {
      await trace.modelCall('gpt-4o-mini', { provider: 'openai' }, async (call) => {
        // ...
        call.score('grounded', true);
      });
      trace.score('relevance', 0.8, { range: [0, 1], version: 'judge-2' });
      traceId = trace.traceId;
    });

    // Later, once the person answered:
    telmoni.score('thumbs', true, { traceId });
    telmoni.score('outcome', 'resolved', { sessionId: 'conv_7' });
    ```

    `value` is a `boolean`, a yes or no; a `number`; or a `string`, a
    category. A handle's `spanId` names its span for a later score. A record's
    trace, steps and calls take `scores: [{ name: 'thumbs', value: true }]`.
  </Tab>
  <Tab value="Go">
    ```go
    trace.Score("relevance", telmoni.Number(0.8),
        telmoni.ScoreOptions{Range: &[2]float64{0, 1}, Version: "judge-2"})
    call.Score("grounded", telmoni.Bool(true), telmoni.ScoreOptions{})
    traceID, spanID := trace.TraceID(), call.SpanID()

    // Later, once the person answered:
    client.Score(telmoni.ScoreTarget{TraceID: traceID}, "thumbs",
        telmoni.Bool(true), telmoni.ScoreOptions{})
    client.Score(telmoni.ScoreTarget{SessionID: "conv_7"}, "outcome",
        telmoni.Category("resolved"), telmoni.ScoreOptions{})
    ```

    A nil handle scores nothing. A record's trace, steps and calls take
    `Scores: []telmoni.RecordedScore{{Name: "thumbs", Value: telmoni.Bool(true)}}`.
  </Tab>
  <Tab value="Rust">
    ```rust
    use telmoni::{Score, ScoreTarget};

    trace.score(Score::number("relevance", 0.8).range(0.0, 1.0).version("judge-2"));
    call.score(Score::boolean("grounded", true));
    let (trace_id, span_id) = (trace.trace_id().to_owned(), call.span_id());

    // Later, once the person answered:
    telmoni.score(&ScoreTarget::trace(&trace_id), Score::boolean("thumbs", true));
    telmoni.score(&ScoreTarget::session("conv_7"), Score::category("outcome", "resolved"));
    ```

    A record's trace, steps and calls take `scores: vec![Score::boolean("thumbs", true)]`.
  </Tab>
</Tabs>

A score that breaks these rules — a name blank or too long, a number that is
not finite or falls outside its range, a range on a yes or no or a category, a
blank category, a version too long, a value of another type, or a target that
names no trace, span or session — is not sent, with one warning, `input`
([Answers and warnings](#answers-and-warnings)), and never raised into your
code; so is one on a handle whose span has ended, which the client's `score`
sends instead, and a span's seventeenth, since a span holds 32 events and its
failure needs one. A body `/v1/scores` refuses is dropped with one warning,
`refused`, one it cannot take just then is sent again as an export is, and
one still failing after an export's attempts is dropped with one warning,
`failed`. A score on a trace continued from another service sends nothing, as
nothing of that trace is sent from this side.

## A trace across services

An agent whose work spans more than one service — an orchestrator handing a
task to a worker, a tool served over HTTP — is still one trace. Before the
request leaves, `inject` writes into its headers the W3C `traceparent` of the
span current inside the trace and the agent as the W3C `baggage` member
`telmoni.agent`, beside whatever members the headers hold already. In the
service that answers, `extract` reads them back as the trace continued there:
the steps and calls it opens carry the caller's trace id and agent and take
the caller's span as their parent, so the trace shows the work where it was
asked for, and the trace list shows one trace, not one a service.

<Tabs items={['Python', 'TypeScript', 'Go', 'Rust']}>
  <Tab value="Python">
    ```python
    # The orchestrator, inside a trace.
    with telmoni.step("delegate"):
        headers = {"Content-Type": "application/json"}
        telmoni.inject(headers)
        requests.post("https://worker.internal/work", json=task, headers=headers)

    # The worker.
    @app.post("/work")
    def work(request):
        trace = telmoni.extract(request.headers)
        with telmoni.step("work", trace=trace):
            ...
    ```
  </Tab>
  <Tab value="TypeScript">
    ```ts
    // The orchestrator, inside a trace.
    await trace.step('delegate', async (step) => {
      const headers = new Headers({ 'content-type': 'application/json' });
      telmoni.inject(headers, step);
      await fetch('https://worker.internal/work', { method: 'POST', headers, body });
    });

    // The worker.
    app.post('/work', async (req, res) => {
      const trace = telmoni.extract(req.headers);
      await trace?.step('work', async (step) => { /* ... */ });
    });
    ```
  </Tab>
  <Tab value="Go">
    ```go

    req, _ := http.NewRequestWithContext(stepCtx, http.MethodPost, "https://worker.internal/work", body)
    client.Inject(stepCtx, req.Header)
    resp, err := httpClient.Do(req)
    step.End()

    // The worker.
    func work(w http.ResponseWriter, r *http.Request) {
    	ctx := client.Extract(r.Context(), r.Header)
    	trace := telmoni.TraceFromContext(ctx)

    ```
  </Tab>
  <Tab value="Rust">
    ```rust

    let mut headers: HashMap<String, String> = HashMap::new();
    telmoni.inject_from(&step.context(), &mut headers);
    // or, with the step attached or a future run with its context: telmoni.inject(&mut headers)
    post("https://worker.internal/work", &headers, &task)?;
    step.end();

    // The worker.

        // ...
    }
    ```

    `inject` and `extract` take any `Carrier`: a type that is both an
    OpenTelemetry `Injector` and `Extractor`, as `HashMap<String, String>`
    is; wrap a request's own headers in one.
  </Tab>
</Tabs>

In TypeScript, `inject` takes the handle to write from, or writes from the
active context where your application runs OpenTelemetry's context manager;
in Rust, `inject` reads the current context, which a handle's `attach()` or
`FutureExt::with_context` sets, and `inject_from` takes a handle's `context()`.
The worker never ends a trace it continued: the orchestrator's own span does,
and until it arrives the trace is open with what the worker sent. Headers that
name no trace — no `traceparent`, no `telmoni.agent`, a malformed one —
continue nothing, and a step opened then is outside a trace and sends nothing.
The headers carry the trace's id and agent and nothing else; a service sending
under another project's key records the spans as that project's own trace, so
a forged header reaches no other tenant. Telmoni's own helpers write and read
the headers; no propagator is set globally, since your application's
propagators are its own.

## The guard

A trace opened with a cap is held to it in the agent's own process, with no
call to Telmoni: `max_steps` caps its steps, and `max_spend`, in US dollars,
what its model calls cost. Once the trace reaches a cap, what it opens next is
refused before it opens: a step past its step cap, and, once what it spent is
its spend cap or more, any step, model call, tool call or retrieval. A call's cost is
known only once it answers, so a trace can spend past its cap by the calls
already open as it crossed: one, where it makes them one at a time.

Each call is counted as Telmoni counts it: its cost as reported in the usage
handed to `answered`; else its tokens at its price in the table each SDK
release carries — LiteLLM's, the one Telmoni
[prices a call by](/docs/api/ingest#what-a-call-cost), by its provider and the
model it answered as, whole; else nothing. The table names each provider as
the GenAI conventions spell it, the spelling the
[field inventory](/docs/api/field-inventory) gives — `openai`, `anthropic`,
`gcp.vertex_ai`, `aws.bedrock` and the rest of its list — so a call naming its
provider otherwise, `gemini` or `bedrock` say, finds no price there. Prices of
your own, handed to the
client as `prices`, come before the table's, for a model it lacks or prices
otherwise than you pay; the SDK alone holds them, so Telmoni's own reads, an
alert on what each trace spent among them, still price that call by the table.
A call answered more than once, as a stream's counts arrive, counts as its
span then holds it: each count and the cost as last given, Go's `Usage` giving
its five counts each time. An answer given after its call ended is not sent
and counts nothing, with one warning; in Rust, `end` takes the call, so none
can come. A call with neither a cost nor a price is never
stopped on cost, and under a spend cap the SDK warns once of each such model.
`spent` reads what a trace's calls have cost so far, as the guard counts them.

<Tabs items={['Python', 'TypeScript', 'Go', 'Rust']}>
  <Tab value="Python">
    ```python
    from telmoni import CapExceededError, Config, Price, Telmoni

    telmoni = Telmoni(
        Config(prices=[Price(provider="vllm", model="llama-3.1-70b", input=2e-7, output=6e-7)])
    )

    try:
        with telmoni.trace("support-bot", max_steps=20, max_spend=0.50) as trace:
            ...
    except CapExceededError as stopped:
        print(stopped.cap, stopped.limit, stopped.used)  # spend 0.5 0.5213
    ```

    `CapExceededError`, a `RuntimeError`, is raised where the step, model
    call, tool call or retrieval would open, naming the `cap` (`steps` or `spend`), its

    failed with its class. A cap that is not above 0 raises `ValueError`, as a
    price that names no provider or model, or is no number from 0, does; a
    cache price not given is the input price.
  </Tab>
  <Tab value="TypeScript">

  </Tab>
  <Tab value="Go">

## What a trace sends

A trace is a trace of its own, at whose root stands the agent's span, named
`invoke_agent <agent>`; opened while one of your application's spans is
current, it is linked to that span rather than nested in its trace. The
agent's span carries its agent (`telmoni.agent`), the user and session you
named (`user.id`, `gen_ai.conversation.id`), the first 32 of its tags Telmoni
would keep, the most it keeps, as `telmoni.tag.<key>`. Every span inside the
trace carries the agent, user and session, so Telmoni knows each span's agent
without waiting for the trace's tree. As the trace opens, the SDK also sends
its opening, `telmoni.trace.start`, a span of no length under the agent's own
carrying the same three, at once rather than with the next batch: the trace
list shows the trace **Running** from its start, and a trace that stops
sending with no end is [left open](/docs/monitoring/alerts#loops-and-stalls)
rather than unseen. It counts against no plan. A trace continued from another
service's headers sends none, nor does a recorded trace. The resource every
span of an export shares names the
SDK (`telemetry.distro.name` `telmoni`, its version, and the OpenTelemetry
SDK's name, language and version) and, where you set them, the deployment:
`deployment.environment.name` from the `environment` option or
`TELMONI_ENVIRONMENT` (`production`, `staging`), and `service.version` from
`release` or `TELMONI_RELEASE` (a version or a commit), which Telmoni keeps as
the `environment` and `release` of every span and the trace list
[filters](/docs/monitoring/traces#filters) by. Either past 128 characters, which
Telmoni would read as no deployment, is left off with one warning. A step is a span named as you named it; a model call is
`<operation> <model>`, the operation `chat` unless you gave `generate_content`,
`text_completion` or `embeddings`, with the model asked for, the
model that answered, the provider and the token counts under the GenAI
conventions' names, each a whole number from 0, another left off the call
with one warning, and the cost you report as Langfuse's `gen_ai.usage.cost`,
a number of US dollars from 0. Where you give it, a model call also carries
how soon its answer began, `gen_ai.response.time_to_first_chunk` in seconds
from 0, taken by its answer (`answered(time_to_first_token=0.35)`,
`{ timeToFirstToken: 0.35 }`, `Answer{TimeToFirstToken: d}`,
`Reply { time_to_first_token: Some(d), .. }`). In Python and TypeScript, a
time below 0 or not finite is left off the call with one warning, as is a
time below 0 in Go. Where you name it, a model call also carries the prompt it
used, by name and version, as `gen_ai.prompt.name` and `gen_ai.prompt.version`,
from `prompt` and `prompt_version` (`promptVersion` in TypeScript, `Prompt` and
`PromptVersion` in Go). Both are metadata, sent in every content mode and never
handed to your [mask](#masking-content) or the
[scrubbers](#scrubbing-secrets-and-personal-data), so a prompt's name names a
prompt and never a person: a person goes in the trace's `user_id`. A recorded
call carries none. A tool call is
`execute_tool <name>`, and a retrieval `retrieval <source>`, or a memory's
search `search_memory`, with what it asked for and how many came back
([a retrieval](#a-retrieval)). A failure is marked by the error's class, as
`error.type`, and an error status; its message is recorded on the span as an
OpenTelemetry `exception` event (`exception.type`, `exception.message`, and
`exception.stacktrace` in Python and TypeScript, where a stack comes cheaply)
and as the status's message, which leave the process only as
[content](#content) does. A type alone, Python's `fail("TimeoutError")`, Go's
`FailWith` or Rust's `fail`, carries no message. The [ingest page](/docs/api/ingest) lists every attribute and what
the server keeps of each.

### Content

Prompts, completions, tool arguments and results, and a retrieval's query and
documents — `input_messages`, `output_messages`, `system_instructions`,
`arguments`, `returned(...)`, `query` — are
recorded on the span and taken off by the exporter before anything leaves
the process. The agent carries its own messages the same way, on its own span:
what it was asked as the trace opens, and what it answered by `answered` (Python's
`trace(input_messages=…)` and `trace.answered(output_messages=…)`, TypeScript's
`{ inputMessages }` and `trace.answered({ outputMessages })`, Go's
`TraceOptions{InputMessages: …}` and `trace.Answered(telmoni.TraceReply{OutputMessages: …})`,
Rust's `TraceOptions { input_messages, .. }` and
`trace.answered(TraceReply { output_messages })`), and a recorded trace its
`input_messages` and `output_messages`, `inputMessages` and `outputMessages`
in TypeScript and Go. An answer given after its trace ended is not sent, with
one warning; in Rust, `end` takes the trace, so none can come. A failure's
message and stack trace — its `exception` event and its status's message —
and every event your code adds to an SDK span through OpenTelemetry, a
[score](#scores)'s own keys apart, are content too; without both locks below, a failed span leaves with its
`error.type` and an error status alone, and no event. They are sent only when the client is built with
`capture_content` on — in code, or by `TELMONI_CAPTURE_CONTENT=1` when it is
built from the environment — **and** the project's content mode, which the SDK
asks the server for before the first content it would send, with an export of
no spans, and learns again from every answer, is `on`; in Python and TypeScript, a setting
that is no boolean, such as `"false"` from the environment, is refused with a
`TypeError`, where Go and Rust take only a boolean. Sent, content is kept as it
arrives, sealed in Postgres alone, for as long as its span (see [what is
dropped at the door](/docs/api/ingest#what-is-dropped-at-the-door)). The
server's own drop at the door is the second lock, not the first.

An image or file a message carries, a part of type `blob` holding its bytes in
base64 in the input or output messages or the system instructions, never
travels inside the span, where it would swell every span that repeats it, past
the 1 MiB an export may hold. Where content is sent, the exporter takes the
SHA-256 of the bytes, puts them to `PUT /v1/media/{sha256}` on the same
endpoint with the same key and the part's `mime_type` as their type
(`application/octet-stream` where it has none, or one blank or of anything
but printable ASCII), once a client for each file, and sends the part as
`{"type": "file", "modality": …, "mime_type": …, "file_id": "telmoni:<sha256>"}`,
its `modality` and `mime_type` kept where it had them. A file past 5 MiB is not
put, and a put that fails is logged once and never costs the batch; either way
the part is sent as the file it names. A part whose content is no base64, and
every `uri` and `file` part, goes as it is. With either lock off, nothing is
put, as nothing of the content is sent.

### Masking content

To send content without what should never leave, a card number or an email
address, give the client a mask: a function of your own, handed each content
field's key and its value, which answers what to send instead, or nothing to
send the span without that field. The exporter calls it where content is sent,
and only there, so on an `off` project, or with `capture_content` off, it is
never called. It is handed the input and output messages and the system
instructions as their JSON, blob parts and all, every attribute of an event
under its own key, a failure's message as `exception.message`, its stack trace
as `exception.stacktrace` in Python and TypeScript, and its status's message as
`otel.status_description`; a value that is no string comes as its JSON, and an
answer the same as what it was handed keeps the value as it was. It runs once a
field each export, before any image is put, so a part it takes out is never
uploaded, and must answer at once, never waiting on the network. A mask that
fails — Python's raise, TypeScript's throw, Go's and Rust's panic, or in Python
and TypeScript an answer that is no string — sends the span without that field,
warned once (`mask_failed`) by the key alone, never its words, which may hold
what it was handed. It sees the content the SDK records, never a span's name, a
tag, a user id or a call's prompt, which are metadata kept on every project, nor an attribute
your code sets on a span itself through OpenTelemetry, which leaves the process
whatever `capture_content` says and which a project keeping content keeps as
[metadata content](/docs/monitoring/content#what-is-kept): keep a person out of
those in your own code. No variable sets one: give it in code.

<Tabs items={['Python', 'TypeScript', 'Go', 'Rust']}>
  <Tab value="Python">
    ```python
    import re

    from telmoni import Config, Telmoni

    CARD = re.compile(r"\b\d(?:[ -]?\d){12,18}\b")

    def mask(key: str, value: str) -> str | None:
        return CARD.sub("[card]", value)

    telmoni = Telmoni(Config(api_key="tm_...", capture_content=True, mask=mask))
    ```
  </Tab>
  <Tab value="TypeScript">

    ```ts
    import { Telmoni } from 'telmoni';

    const telmoni = new Telmoni({

      mask: (key, value) => value.replace(CARD, '[card]'),
    });
    ```
  </Tab>
  <Tab value="Go">

    ```go
    })
    ```
  </Tab>
  <Tab value="Rust">

    ```rust
        })),
        ..Config::from_env()
    });
    ```

### Scrubbing secrets and personal data

With content on, the SDK reads each content field it sends for secrets before
the span leaves the process: the fields your [mask](#masking-content) is
handed, after it, and after any image is lifted out of a message, so an
image's bytes are never read. Each match is replaced by a marker naming its
kind, `[secret: aws_key]`:

| Kind | What it finds |
|---|---|
| `private_key` | A PEM private key, from `-----BEGIN … PRIVATE KEY-----` to its end, or to the end of the JSON string it was cut off in |
| `connection_string` | A URL that holds a password, `postgres://app:password@db/orders` |
| `jwt` | A JSON Web Token |
| `anthropic_key`, `openai_key`, `stripe_key`, `github_token`, `slack_token`, `aws_key`, `gcp_key`, `telmoni_key` | Each provider's key, by its shape |
| `password`, `token` | The value beside `password`, `passwd` or `pwd`, of 8 characters or more; beside `secret`, `token`, `api_key`, `access_key`, `client_secret`, `accountkey` or `sharedaccesskey`, of 16 or more holding a letter and a digit |

Turn personal data on too and, after the secrets, it replaces `email`
addresses; `phone` numbers written with a `+` or separators; `card` numbers
that pass Luhn's check and start as an issuer's do, 2 to 6, so a timestamp or
an id is left alone; US social security numbers (`ssn`); `iban`s that pass
their check; `ip` addresses, v4 and v6; and the user's folder in a
`home_path`, `/home/dana` or `C:\Users\dana`, each `[pii: email]` and so on.
No pattern finds a name, a street address, text inside an image, or a secret
of a shape these rules do not know: a [mask](#masking-content) is for what
your application alone knows.

A span whose content a scrubber changed carries `telmoni.scrubbed`, the count
of each kind it replaced and never a value, `{"pii:email":2,"secret:aws_key":1}`,
which the trace's page shows beside the span's content. A scrubber that fails on
a field sends the span without that field and counts it under `dropped:` and
the field's key: it never sends the field as it was.

The secrets scrubber is on wherever content is sent: `scrub_secrets` /
`scrubSecrets` / `ScrubSecrets` / `scrub_secrets` set false, or
`TELMONI_SCRUB_SECRETS=0`, turns it off. The personal-data scrubber is off in
the SDKs and on in the [Claude Code, Codex and Antigravity plugins](/docs/api/coding-agents):
`scrub_pii` / `scrubPii` / `ScrubPII` / `scrub_pii` set true, or
`TELMONI_SCRUB_PII=1`, turns it on. Every client reads the two variables where
your code leaves its switch unset, however the client was made; a switch set
in code stands.

Both take time in proportion to a field's size, whatever it holds. On a 1 MiB
tool output, measured on a busy eight-core laptop:

| SDK | Secrets | Secrets and personal data |
|---|---|---|
| Python | about 50 ms | about 180 ms |
| TypeScript | about 25 ms | about 150 ms |
| Go | about 25 ms | about 60 ms |
| Rust, a release build | about 45 ms | about 70 ms |

### Beside your own OpenTelemetry

The SDK builds every part of its tracer provider itself — resource, sampler,
limits, batching — so none of your `OTEL_*` variables reaches it, and it
neither replaces your provider nor sends your spans to Telmoni. A trace opened
while one of your application's spans is current is a trace of its own, linked
to that span rather than nested in its trace, so a request that runs an agent
a hundred times shows a hundred traces, each whole; your spans opened inside
it nest under the agent's span. Each trace takes the decision your own sampler
gives it as it opens — given as the `sampler` option in every SDK, Python
falling back to your provider's sampler when you give none — and your
application's own spans inside it follow that flag, so its sampling rate holds
inside traces as outside them. Every trace is sent whatever the flag says, one
beside an application span the application does not sample too. In Rust, the
link and the nesting take your application on the SDK's `opentelemetry` minor,
which `telmoni::opentelemetry` re-exports: cargo builds each 0.x minor apart,
each with a current context of its own.

### Answers and warnings

The SDK batches spans and sends them in the background, on a bounded queue,
so a slow Telmoni never slows an agent. The queue holds 2,048 spans and a batch
512, sent every 5 seconds, each of which you can set: Python's
`Telmoni(batching=Batching(...))`, TypeScript's `processor` hook, Go's
`WithBatching` and Rust's `Hooks::batching`; a record larger than the queue is
refused, so raise it for records that long. Each request times out after 10
seconds. It retries a `429`, `502`, `503` or `504`, the statuses OpenTelemetry
retries, after its `Retry-After`, waiting at most 60 seconds, and one with no
`Retry-After`, as a load balancer's `502` for a server restarting, or a request
that failed or timed out before its answer's head was whole, after 1 second,
then 2; after three attempts in all it drops the batch with one warning. Any
other refusal is logged once and never retried, and an answer whose body
breaks after its head, or runs past the 10 seconds, is decided by its status,
read as far as it came. A batch whose body would pass the
1 MiB [ingest](/docs/api/ingest#refusals) takes, or that holds more than its
1,000 spans, is sent in halves, each within both, and a span that alone passes
the 1 MiB is sent, where it carries content the project keeps, without its
longest content — a content field, or any value past 1,024 characters, which
such a project keeps as content — the longest first and as few as fit it, each named in
`telmoni.content_cut`; else without the attributes ingest drops for their
length — a key past 128 characters, a value past 1,024 — each with one warning. Once a part fails
as the rest would, Telmoni out of reach or busy past the retries, or the key
refused, the parts after it are dropped with it; past a part refused for what it
holds, they are sent. A number attribute JSON cannot carry, `NaN` or an
infinity, is sent as no value, and so dropped, and a whole number past 64 bits
as its text or a double, never costing its batch. Each attempt carries
`Telmoni-Sent-At`, the agent's clock as it leaves, so
[ingest](/docs/api/ingest#what-is-kept) can move
a trace from a clock a time zone or a date out as one. A flush waits up to 30 seconds, and a
shutdown drains for as long, then gives up what is left, sending nothing more. An attribute the
server drops is logged once: content with the project's content mode, which
decides the drop, and a link to [what is dropped at the
door](/docs/api/ingest#what-is-dropped-at-the-door); text the field inventory
does not name with the `telmoni.tag.<key>` that would keep it; and a tag past
its project's cardinality cap with how tags keep, a few keys of a few values
each.

Each warning comes with what became of its spans, so code that reads the
warnings need not read their words: its kind, and for an export's own failure
the status it last met and the problem type its body named. `refused` is an
export refused for good and `failed` one that failed every attempt, each batch
dropped; `queue_full` spans dropped with the queue full; `export_error` a batch
its own export dropped, unable to encode it or failing; `too_large` a span past the 1 MiB dropped and `trimmed`
one sent without its longest content or its long attributes; `dropped`, `span_refused` and `said` the
server's answer, the rest of the export kept; `input` something the SDK was
handed, fixed, cut or left off; `upload_failed` an image or file that could
not be put, with the status its put met where one came, its span sent naming
it; and `mask_failed` a span sent without a content field your mask failed on. Python sets it on the log record as
`telmoni_warning`, a `WarningInfo`; TypeScript hands it to the `warn` hook as its
second argument, a `Warning`; Go logs it as the record's `kind`, `status` and
`problem_type` attributes; and Rust hands it to `Hooks::warn` as its second
argument, a `Warning`, and to `tracing::warn!` as fields of the same names.

### The key on the wire

The key travels as a bearer over HTTPS. Plain HTTP is accepted only to this
machine, for a server you run beside the agent: `localhost`, a name under it,
an address in `127.0.0.0/8`, or `::1`, an IPv4-mapped address such as
`[::ffff:127.0.0.1]` counting as its IPv4. Python, TypeScript and Go refuse any
other `http://` endpoint when the client is built, and Rust when the first
export would go, with one warning. An endpoint given without a scheme gets
`https://`, or `http://` for this machine, as the CLI reads one; any scheme
but those two is refused the same way, as is an endpoint the four SDKs could
read two ways: one that is not printable ASCII once the whitespace around it
is trimmed, or holds credentials, a percent-escape, a query, a fragment, a `.`
or `..` segment or a character a URL parser would escape, such as a space or
`|`, or a port of 0 or past 65535, or whose host is neither a name of letters,
digits, dots, hyphens and underscores, in labels of 1 to 63 characters with no
hyphen at either end and the last no number, nor an IPv4 address in four
decimal parts, nor an IPv6 address in brackets. Write an
address in full, `127.0.0.1` rather than `127.1`, and a name in another script
in its `xn--` form. No SDK follows a redirect, which could carry the key to
another host, nor sends to this machine through a proxy, whatever the proxy
variables name, since the proxy would read it; and the key never appears in a
log, a warning or an error.

`environment` and `release` name the deployment every span is sent from, as
the resource's `deployment.environment.name` and `service.version`; a blank
one is unset, and nothing is sent for one unset. `prices` hands
[the guard](#the-guard) prices of your own, and nothing of them is sent.
`mask` is your own function over content, [masking content](#masking-content),
and `scrub_secrets` and `scrub_pii` turn the
[scrubbers](#scrubbing-secrets-and-personal-data) off and on.

Each SDK keeps the API key out of the configuration's printed form: Rust's
`Debug` shows `<redacted>` in its place and serialization skips it; Python
holds it as a `Secret` that `repr`, `str` and `dataclasses.asdict` show
redacted; Go holds it as a `Secret` too, made with `telmoni.NewSecret`, which
prints redacted, or as an address inside a struct of yours that `%+v` or a
logger prints field by field, never as the key; JSON skips it, YAML, TOML and
XML write it redacted, and `gob` refuses it; TypeScript holds `apiKey` as a
non-enumerable property, which `console.log` and `JSON.stringify` pass over.

## Environment variables

`from_env` / `fromEnv` / `NewFromEnv` / `Config::from_env` read:

| Variable | Description | Default |
|---|---|---|
| `TELMONI_ENDPOINT` | The origin ingest is served on: Telmoni's machine host, or your own deployment's | `https://api.telmoni.com` when unset or blank |
| `TELMONI_API_KEY` | An [API key](/docs/api/api-keys) holding the **ingest** scope, created on a project's API keys page | None |
| `TELMONI_ORG` | The organization's ID (`org_...`), held and not sent: the key names the project | None |
| `TELMONI_ENVIRONMENT` | The deployment this process runs in — `production`, `staging` — sent as `deployment.environment.name`, up to 128 characters | None: nothing is sent |
| `TELMONI_RELEASE` | The release this process runs — a version or a commit — sent as `service.version`, up to 128 characters | None: nothing is sent |
| `TELMONI_CAPTURE_CONTENT` | `1` turns on [content](#content); anything else — `0`, `true`, `yes` — or nothing leaves it off, the blanks about it trimmed. A setting made in code over what `from_env` read stands, on or off | Off |
| `TELMONI_SCRUB_SECRETS` | `0` turns off the [secrets scrubber](#scrubbing-secrets-and-personal-data); anything else, or nothing, leaves it on, the blanks about it trimmed. Read by every client where its code leaves the switch unset | On |
| `TELMONI_SCRUB_PII` | `1` turns on the [personal-data scrubber](#scrubbing-secrets-and-personal-data); anything else, or nothing, leaves it off, the blanks about it trimmed. Read by every client where its code leaves the switch unset | Off |

Every SDK reads these eight and no others. OpenTelemetry's own `OTEL_*`
variables are your application's, for its own exporters, and change nothing
of the SDK's: `OTEL_RESOURCE_ATTRIBUTES` in particular reaches nothing the
SDK sends.
