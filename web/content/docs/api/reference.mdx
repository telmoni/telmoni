The Telmoni API is an HTTP interface under `/v1`. Authenticated by a
[project API key](/docs/api/api-keys), it reads a project as the console does:
its organization, its traces with their spans and, if asked, their
content, its totals by the hour or the day, its incidents and its agents'
changes, so a script, a notebook or a BI tool can work with them. The routes here need the `read`
scope, and write nothing. Spans go to a lane of their own,
[`/otlp/v1/traces`](/docs/api/ingest), with a key holding the `ingest` scope, as
do the two writes under `/v1`: `PUT /v1/media/{sha256}`, where our SDKs keep a
file a message carried ([Ingest](/docs/api/ingest)), and
[`POST /v1/scores`](#post-v1scores), the scores of what already ended. Every
route under `/v1`, those among them, is also described as an OpenAPI 3.1 document,
[`contract/openapi.json`](https://github.com/telmoni/telmoni/blob/main/contract/openapi.json)
in the platform's repository, generated from the same tables the server routes by.

## Base URL and authentication

```text
https://api.telmoni.com/v1
```

*(On a self-hosted instance, replace `https://api.telmoni.com` with your
deployment's own machine host, or with its console's host where the machine
lanes are routed by path: [Self-hosting → Production](/docs/self-host/production#reverse-proxy-configuration).)*

Authenticate all requests by including your project API key as a bearer token:

```http
Authorization: Bearer tm_...
```

Requests lacking a valid or live key return `401 Unauthorized`, as a problem
document; a revoked, expired or unknown key, or one whose organization is
being deleted, answers the same way:

```json
{
  "type": "/errors/auth/invalid-token",
  "title": "invalid token",
  "status": 401,
  "detail": "a live tm_ API key is required"
}
```

A live key without the `read` scope is refused with `403 Forbidden` and
`/errors/authz/forbidden` ([API keys](/docs/api/api-keys)).

## HTTP methods

The read routes accept `GET` and `HEAD`, and `/v1/scores` `POST` alone. Any other method returns `405 Method Not
Allowed` with an `Allow` header and a problem document, except `OPTIONS`, which
answers `204` with `Allow: GET, HEAD, OPTIONS`.

## Rate limits

| Scope | Limit |
|---|---|
| Per API key | 600 requests / minute |
| Per source IP address (an IPv6 address by its /64) | 1,200 requests / minute |

The [CLI](/docs/api/cli)'s lanes under `/cli/v1` are metered the same way: 600
requests a minute a bearer, and 120 an address, the few a sign-in's polls and a
refresh take.

Exceeding a rate limit returns `429 Too Many Requests` along with a
`Retry-After` header. See [Errors](/docs/errors). The server meters each
itself, the address read past the proxies in front of it
(`TRUSTED_PROXY_HOPS`), and shares the counts between its replicas through
Redis.

## `GET /v1/organization`

Retrieves the organization associated with the presented token.

### Response

`200 OK` `application/json`

```json
{
  "organization_id": "org_019a0b8c3f2e7d41",
  "slug": "acme-corp",
  "name": "Acme Corp",
  "owner": {
    "email": "you@example.com",
    "display_name": "Sam Rivera"
  }
}
```

- `organization_id`: The unique, immutable identifier of the organization.
- `slug`: The first segment of the organization's console URLs (`/acme-corp`).
  It changes only when the organization's URL is changed in its Settings (see
  [Name and URL](/docs/workspace/organizations-and-projects#name-and-url));
  `organization_id` never does.
- `name`: The organization's name.
- `owner`: The organization Owner's `email` and `display_name` (`null` when
  they have not set one). `owner` itself is `null` if the organization has no
  owner on record.

## `GET /v1/traces`

A page of the project's traces in the window, the same list the project's
**Traces** page shows, with how many the filter admits. It takes the page's
query, each parameter repeatable where the page lets you pick several values:

- `days`: How many days back, 1 to 360; 7 when left out. A window reaches back
  no further than your plan keeps spans, and the answer's `days` says how far
  it read.
- `agent`, `user`, `session`, `status` (`ok`, `error` or `cancelled`),
  `model`, `tool`, `environment`, `release`, `prompt`, `tag` as `key:value`,
  and `prompt_version` as `name:version`, a prompt's version under its name:
  each narrows the list to traces that match one of its values.
- `score`: A score's name, up to 64 characters, with `score_min` and
  `score_max`, each optional, bounding its value: narrows the list to traces
  carrying a score of that name within them. A bound without `score` is a
  `400`.
- `sort` and `dir` (`asc` or `desc`): The column and the direction, as the page
  sorts.
- `limit` and `page`: The page's size and which page, from 1.

An unknown parameter, or a value that does not parse, is a `400`.

### Response

`200 OK` `application/json`

```json
{
  "traces": [
    {
      "trace_id": "0191a3b47c2e7d3f8e4a5b6c7d8e9f01",
      "agent": "nightly-report",
      "status": "ok",
      "started_at": "2026-11-01T09:00:00Z",
      "duration_ms": 1500,
      "spans": 2,
      "input_tokens": 1200,
      "output_tokens": 340
    }
  ],
  "days": 7,
  "limit": 50,
  "page": 1,
  "total": 1,
  "more": false,
  "sort": "started",
  "dir": "desc"
}
```

Each trace carries every column of the page's table: its id, agent, end
user and session, how it ended, when it started and ended, its spans, steps,
model and tool calls, failures and tokens. The example shows a few. `more`
says whether a later page holds more.

## `GET /v1/traces/{trace_id}`

One trace's spans, the agent's own among them, in the order they started, and
what the trace spent, by its id, 32 hex digits. A trace the project does not
hold, or one older than your plan keeps, is a `404`. With `content=true`,
each span's content comes too,
where the project keeps it ([Content](/docs/api/field-inventory#content)); every such
read is filed in the organization's audit log, its actor `key:` and the key's
ID, as a person's read in the console is filed under theirs. A `HEAD` opens no
content, so it files nothing.

### Response

`200 OK` `application/json`

```json
{
  "trace_id": "0191a3b47c2e7d3f8e4a5b6c7d8e9f01",
  "spans": [
    {
      "span_id": "00f067aa0ba902b7",
      "trace_id": "0191a3b47c2e7d3f8e4a5b6c7d8e9f01",
      "kind": "model_call",
      "name": "chat claude-sonnet-5-5",
      "status": "ok",
      "model": "claude-sonnet-5-5",
      "input_tokens": 1200,
      "output_tokens": 340
    }
  ],
  "truncated": false,
  "spend": { "spent": 0.0087, "unpriced": [] },
  "content": null
}
```

- `spans`: Each span's every field, as the trace's page reads it; the example
  shows a few.
  A model call's `output_speed` is its output tokens/s after its first token:
  `(output_tokens - 1) / (duration_seconds - time_to_first_token_seconds)`,
  calculated at stored microsecond precision. It is `null` on other span kinds,
  without finite nonnegative first-token timing, with fewer than two output
  tokens, or without a positive remaining duration and finite positive rate.
  Inclusive output includes reasoning; the value is an estimate from reported
  first-chunk timing, not a measurement of every token interval. This is a
  derived read field, not an attribute an SDK sends.
- `truncated`: Whether the trace holds more spans than the answer carries.
- `spend`: What its model calls cost, in US dollars, and the models no price
  covers; `null` when it could not be read.
- `content`: Without `content=true`, `null`. With it, a list of
  `{ "trace_id", "span_id", "fields" }`, each field by its name: empty where
  the project kept none, `null` where it could not be opened just then.

Where a trace's `content` is opened, it carries beside its spans' fields the
trace's [score comments](/docs/monitoring/scores#a-scores-comment), each under a
span id that no span's 16 hex digits can be: `score/` and the score's id.

## `GET /v1/metrics`

The project's totals over the window, by the hour or the day, read from the
totals Telmoni keeps an hour at a time.

- `days`: The window, 1 to 360 days back from now; 7 when left out. The
  totals are kept thirteen months on every plan, so the window reaches past
  what your plan keeps of the spans.
- `step`: `day`, the default, or `hour`, the default for a day's window, each
  starting on the hour or at midnight UTC.
- `group`: Splits each step by one of `agent`, `model`, `provider`, `tool`,
  `status`, `fault`, `environment` or `release`, from the totals; or by `tag`, `user`
  or `session`, from the spans, no further back than your plan keeps them,
  which `days` in the answer then says. Only tool calls carry a `tool`; every
  other span falls under the empty value. Only a span that names a model
  carries a `model`, which the SDKs' model calls do and their agents' own spans
  do not: a model's points then count its calls, and the traces fall under the
  empty value.
- `tag`: With `group=tag`, the tag key whose values split each step, 1 to 64
  characters.

With `group=fault`, each point's `value` is `rate_limited`, `overloaded`,
`timeout`, `context_length`, `unauthorized`, `invalid_output`, `refused`,
`truncated` or `other`; the empty value holds spans without a fault. A
category's `spans` counts spans, including successful model calls whose
finish reasons indicated refusal or truncation. Its `failed` still counts
only spans with error status. The trace detail's spans also carry `fault`,
one of these words or `null`. No error message is used to classify a fault.

Each point's token counts are inclusive: input includes cache reads and writes,
and output includes `reasoning_output_tokens`. The reasoning count is zero
where none was reported, is metadata in every content mode, and is priced
once as output. Cache share is the sum of cache-read input divided by the sum
of input, unavailable when that denominator is zero.

### Response

`200 OK` `application/json`

```json
{
  "days": 7,
  "step": "day",
  "group": "model",
  "points": [
    {
      "at": "2026-11-01T00:00:00Z",
      "value": "claude-sonnet-5-5",
      "spans": 412,
      "failed": 3,
      "traces": 0,
      "failed_traces": 0,
      "input_tokens": 512000,
      "output_tokens": 98000,
      "cache_read_input_tokens": 120000,
      "cache_write_input_tokens": 4000,
      "reasoning_output_tokens": 12000,
      "spend": 2.34,
      "duration_ms": { "avg": 1840.5, "p50": 1500, "p90": 3100, "p99": 7400 },
      "trace_duration_ms": { "p50": null, "p95": null, "p99": null }
    }
  ],
  "truncated": false
}
```

Points come oldest first, and only for an hour or a day that holds a span.
`value` is the group's value, left out without `group`. A split by `tag`,
`user` or `session` names the ten values that spent most over the window and
sums the rest in points carrying `"others": true` and an empty `value`; a
call counts for its trace's value, a trace that carries none under the empty
value. `failed` counts the
spans that ended in error, `traces` and `failed_traces` the traces that ended and
those that failed. `spend` is what the model calls cost in US dollars, each as
it reported, else its tokens at the project's own price or the price table's,
priced as it is read ([What a call cost](/docs/api/ingest#what-a-call-cost)),
and scaled by its trace's [sample rate](/docs/api/ingest#what-is-dropped-at-the-door),
so a trace a plan kept one in ten of counts ten times.
`duration_ms` is every span's, `trace_duration_ms` the traces' alone. The durations
are in milliseconds, and a percentile is `null` where none can be read. `truncated` is `true` past 10,000
points, the oldest left out: ask for a shorter window, or a day at a time.

## `GET /v1/incidents`

The project's incidents, the same list the **Incidents** page shows: those not
resolved first, then the newest, 200 at most. With `trace`, a trace's id, only
the incidents whose notices showed that trace.

### Response

`200 OK` `application/json`

```json
{
  "incidents": [
    {
      "id": "019a4e2f-1c3d-7a5b-9e8f-0a1b2c3d4e5f",
      "rule_id": "019a4e2f-0b2c-7d4e-8f9a-1b2c3d4e5f60",
      "rule_name": "Failures on checkout",
      "status": "open",
      "severity": "alert",
      "value": 0.12,
      "opened_at": "2026-11-01T09:05:00Z",
      "acknowledged_at": null,
      "acknowledged_by": null,
      "resolved_at": null,
      "resolved_by": null,
      "reopened": 0,
      "told_to": [],
      "traces": ["0191a3b47c2e7d3f8e4a5b6c7d8e9f01"],
      "changes": [
        {
          "agent": "checkout",
          "environment": "production",
          "kind": "release",
          "value": "2026.11.3",
          "changed_at": "2026-11-01T08:51:00Z",
          "trace_id": "0191a3b46a1d7c2e9d3f4a5b6c7d8e90",
          "capped": false
        }
      ],
      "changes_more": false
    }
  ]
}
```

- `status`: `open`, `acknowledged` or `resolved`; `severity` is `warning`,
  `alert` or `no_data`, and `value` what the alert read when it crossed.
- `acknowledged_by` and `resolved_by`: Who took or resolved it by hand, by
  user ID, or `null`.
- `told_to`: The connections its notices were sent to. `traces`: The traces
  its notices showed, oldest first.
- `changes`: What the agents its alert or monitor reads
  [changed to](/docs/monitoring/alerts#what-changed-before-it) in the 24
  hours before it opened, each as [`GET /v1/changes`](#get-v1changes) answers
  one, the newest first, 20 at most: `[]` where nothing changed, and `null`
  where they could not be read, which is not that nothing changed. They are
  read as the incident is answered, so a change found after it opened is
  among them. `changes_more`: Whether it had more than are answered.

`GET /v1/incidents/{id}` answers one incident in the same shape, or `404`
for an ID the project does not hold.

## `GET /v1/changes`

The project's agents' changes, the ones the **Traces** page marks on its bars:
each the first trace of an agent, in one environment, to carry a release, a
model or a prompt's version its traces there had not carried in the 30 days
before ([Changes](/docs/monitoring/traces#changes)). The newest first, 500 at
most. It takes:

- `days`: How many days back, 1 to 360; 7 when left out, and no further than
  your plan keeps spans.
- `agent` and `environment`: each narrows the list to changes that match one of
  its values.

An unknown parameter, or a value that does not parse, is a `400`.

### Response

`200 OK` `application/json`

```json
{
  "days": 7,
  "more": false,
  "changes": [
    {
      "agent": "support",
      "environment": "production",
      "kind": "prompt",
      "prompt": "support-reply",
      "value": "3",
      "changed_at": "2026-11-01T09:05:00Z",
      "trace_id": "0191a3b47c2e7d3f8e4a5b6c7d8e9f01",
      "capped": false
    }
  ]
}
```

- `kind`: `release`, `model` or `prompt`; `value` is the release, the model,
  or the prompt's version, and `prompt` its name, on a prompt's change alone.
- `environment`: The environment its spans were sent from, empty where they
  named none.
- `changed_at`: When the trace that first carried it started; `trace_id` that
  trace, which [`GET /v1/traces/{trace_id}`](#get-v1tracestrace_id) reads
  while it is kept.
- `capped`: `true` where an agent made more than 24 changes of one kind in a
  UTC day: on the last one listed, since the rest are not.
- `more`: Whether the window held more than the 500 listed.

## `POST /v1/scores`

Scores of traces, spans or sessions that already ended, a person's thumbs-up on
an answer, say, or a check a job ran overnight, under a key holding the
`ingest` scope. A score of a span still open rides on it instead, as the
[evaluation event](/docs/api/ingest#scores); our [SDKs](/docs/api/sdks#scores)
send either, and the client's `score` sends this. One request carries 1 to 100
scores:

```json
{
  "scores": [
    {
      "id": "0b9a3f0e-6c1d-4f7a-9e2b-5d8c7a6b4e31",
      "trace_id": "0191a3b47c2e7d3f8e4a5b6c7d8e9f01",
      "name": "thumbs",
      "data_type": "boolean",
      "value": 1
    },
    {
      "trace_id": "0191a3b47c2e7d3f8e4a5b6c7d8e9f01",
      "span_id": "00f067aa0ba902b7",
      "name": "relevance",
      "data_type": "number",
      "value": 0.8,
      "range_min": 0,
      "range_max": 1,
      "version": "judge-2"
    },
    {
      "session_id": "conv_7",
      "name": "outcome",
      "data_type": "category",
      "categories": ["resolved"]
    }
  ]
}
```

- What it scores: a `trace_id`, 32 hex digits; a `trace_id` and a `span_id`,
  16 hex digits; or a `session_id`, up to 200 characters, as the session's
  spans send it, kept hashed as they are. It is not looked up, since a trace's
  spans may land after its score: a score of a trace that never arrives shows
  nowhere, and leaves with retention.
- `name`: 1 to 64 characters. `data_type`: `number`, with a finite `value`,
  within `range_min` and `range_max` where it names them; `boolean`, with a
  `value` of 1 or 0; or `category`, with 1 to 10 distinct `categories`, each
  up to 64 characters.
- `version`: Optional, what scored, up to 64 characters. `id`: Optional, a
  UUID of yours, under which a score sent again replaces itself, so a retry
  keeps it once; our SDKs send one with every score.

A score is metadata, kept in every
[content mode](/docs/workspace/organizations-and-projects#a-projects-content-mode).

### Response

`204 No Content` once every score is kept. A request with no score, more than
100, a body past 512 KiB, or one breaking a score's rules is refused whole
with `400`, its `detail` naming the score by its place (`scores[1]: …`), and
nothing is kept. A request is metered as an export to
[ingest](/docs/api/ingest) is, and an organization paused for its payment is
refused with `402`, as its exports are.

## Errors

Every error response is an RFC 9457 problem document
(`application/problem+json`) with a structured error type. A `401` carries a
`WWW-Authenticate: Bearer` header, and a `429` or a feature-off `503` a
`Retry-After` header. Full details and status codes are cataloged in
[Errors](/docs/errors), including the two the server's door answers for a method
or a path no lane takes.

If the API is switched off for your organization or the deployment, requests
respond with `503 Service Unavailable` and the `/errors/tenant/feature-off`
problem type. A `503` with `/errors/auth/identity-unavailable`, and no
`Retry-After`, means Telmoni could not read the key or the API's switch just
then: retry, and don't take the key for revoked.
