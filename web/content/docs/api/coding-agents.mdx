title: "Coding agents"
description: "Telmoni's plugins for Claude Code and Antigravity: each turn of the coding agent you already run, recorded as a run with no code, metadata alone unless you turn its conversation on."
---

Telmoni's two plugins record each turn of Claude Code or Antigravity as a
[run](/docs/api/sdks#a-run) in Telmoni, with no code: the models it called
and their tokens, the tools it used, and Claude Code's subagents, each with its
times and whether it failed. Unless you turn [content](#a-turns-conversation)
on, a plugin never sends a prompt, a reply, a thought, a tool's input or
output, a command, a file's path or the folder you work in: a local model named
by the path to its file is sent by the file's name alone.

| Agent | Plugin | Package | Runs as |
|---|---|---|---|
| **[Claude Code](#claude-code)** | [`telmoni/claude-code-observability-plugin`](https://github.com/telmoni/claude-code-observability-plugin) | the repository itself | `claude-code` |
| **[Antigravity](#antigravity)** | [`telmoni/antigravity-observability-plugin`](https://github.com/telmoni/antigravity-observability-plugin) | the repository itself | `antigravity` |

Each plugin is built on the [TypeScript SDK](/docs/api/sdks), bundled with it
into JavaScript committed in the repository, so nothing is built or fetched as
it installs or first runs. It sends what the SDKs send, under a
[project API key](/docs/api/api-keys) holding only the **ingest** scope
(**Send spans**). A self-hosted Telmoni's machine host is read
[as the SDKs read one](/docs/api/sdks#the-key-on-the-wire): given without a
scheme, it is `https://`, or `http://` for this machine, the only host plain
HTTP goes to. Each needs [Node.js](https://nodejs.org) 22 or later on your
`PATH`; without it the hook does nothing and writes no log, so
`node --version` in the shell your agent starts in is the first thing to
check. Claude Code also needs git, with which it adds the plugin's
marketplace.

## What a turn records

A turn — from your prompt to the agent's last reply, or to your interruption —
is one run of the agent, and your session is the run's session
(`gen_ai.conversation.id`), so the console groups a session's traces
together ([Sessions and users](/docs/monitoring/traces#sessions-and-users)). Inside the run:

- **the model's work**, a model call per reply with its model, its provider,
  named as the GenAI conventions and the console's prices name it
  (`aws.bedrock` for Claude Code on Bedrock), and its token counts, the
  cache's reads and writes among them, counted as the GenAI conventions count
  them;
- **each tool call**, by its name, with its time, failed where the tool failed
  and cancelled where it was stopped or never answered;
- **each compaction** of the context as a turn goes on, a step named
  `compaction`;
- in Claude Code, **each subagent**, a step named by its kind
  (`subagent Explore`), holding its own model and tool calls and its own
  subagents' steps, and **the skills the turn ran**, by name, as the tag
  `skills`; the run's release is the version of Claude Code that ran the turn;
- in Antigravity, **each API error**, as a failed model call named by its
  kind. A model call names the conversation's model with its effort apart:
  `gemini-3.8-flash-low` goes as `gemini-3.8-flash` at the reasoning level
  `low`, under the provider `gcp.vertex_ai`.

An interrupted turn is a cancelled run, and a turn an error ended a failed one,
named by the error's kind (`rate_limit`), never its message; in Antigravity, so
is a turn that hit its limits (`max_invocations`). A turn is sent once it has
ended. If Telmoni cannot be reached or is busy, if its database
fails it (`500` `/errors/internal/database`), or if it refuses the key or the
endpoint, the turn is sent again as the session's next turn ends, the
session's later turns waiting for it, or, once the session has ended, as any
session's next turn ends. One Telmoni took in part, or refused for good — for
what it holds (`400`, `413`), for a paused organization (`402`) or for any
other fault of its own (`500`) — is logged and not sent again. Where Telmoni
reaches its Redis, a copy that arrives within the hour of the first is stored
once: its run's id is derived from the session and the turn, and every span's
from the run's.

**What is never read.** With content off, of what Claude Code writes down, its
plugin reads only names, ids, times, counts and flags: each entry's kind, id,
time and outcome, a reply's model, provider and token counts, a tool call's
name, and a subagent's kind. It also reads the skill a `Skill` call names,
which it sends as the tag `skills`, the kind an `Agent` or `Task` call names and
whether it runs in the background, whether a tool result says a subagent went
on in the background, the tool call a background task's notice names, the
subagent a report handed back names, whether a row is a compaction's summary, and
whether a prompt is empty, opens with a tag or marks an interruption, which it
never keeps; and the [tags](#tags) you set. A name is sent only as a plain
name: a model named by a path goes as its file's name or `unknown`, and a
tool, skill or subagent name holding anything else, as a model may write, as
`unknown`. It never keeps or sends a prompt or a reply, the model's thinking,
a compaction's summary, a tool's input or output beyond that skill's name, a
command, the path or contents of a file you work on, the working folder, a
session's title or anyone's email, whatever the project's content mode.

Of what Antigravity writes down, its plugin reads only each step's kind, time
and status, each model call's tokens, each tool call's name, a command's exit
code and an error's code; of what its hook is handed, the conversation's id,
the transcript's path, the model's name, why the turn ended and whether the
conversation is idle, and the first workspace folder, only to find the
[tags](#tags) file above it. It never keeps or sends your prompt, a reply, the
reasoning, a tool's arguments or output, a file's path or contents, the
workspace's folders, the transcript's path, a compaction's summary or an
error's message, whatever the project's content mode.

### A turn's conversation

A plugin can send what was said too, under the same two locks as the
[SDKs' content](/docs/api/sdks#content): your switch, set beside the plugin's
key, and the project's [content mode](/docs/workspace/organizations-and-projects#a-projects-content-mode), which must be
`on`. With either off, nothing of the conversation leaves your machine. The
switch travels with the key: a key in the environment takes
`TELMONI_CAPTURE_CONTENT=1` there, `1` alone, as the SDKs read it, never a
switch from anywhere else. A key in Claude Code's plugin settings takes
**Capture content** in `/plugin configure`
(`{"TELMONI_CAPTURE_CONTENT": true}` through `--values-stdin`), and a key in
Antigravity's key file takes `"captureContent": true` beside it. A plugin takes
no [mask](/docs/api/sdks#masking-content), its hook running no code of yours:
with both locks on, a turn is sent as it was said, but for what the SDK it
sends through scrubs first. In each plugin both of its scrubbers are on:
secrets, and personal data such as email addresses, phone numbers and card
numbers, each replaced by a marker like `[secret: aws_key]` or `[pii: email]`
([what each finds](/docs/api/sdks#scrubbing-secrets-and-personal-data)). Each
is a switch beside the content's: **Scrub secrets** and **Scrub personal
data** in Claude Code's `/plugin configure`, `"scrubSecrets": false` or
`"scrubPii": false` in Antigravity's key file, and a key in the environment
takes `TELMONI_SCRUB_SECRETS=0` or `TELMONI_SCRUB_PII=0` there. No pattern
finds a name or a street address.

On, a Claude Code turn carries its conversation as Claude Code recorded it: your prompt,
with its images, as the run's input, and the last reply as its output; each
model call's reply, with the reasoning the agent wrote in plain text, never an
encrypted or redacted thought; each tool call's input and output; and a
subagent's task and answer on its step. Each model call carries what it was
handed since the call before: your prompt for a turn's first, a subagent's task
for its first, and the tools' results for the rest; a compaction's step carries
its summary. An image goes as the SDKs send one, put aside under `/v1/media`
and named in the message. Still never sent: your email and the workspace's
folders, beyond what you or the agent wrote in the conversation itself. An
Antigravity turn carries your prompt as you typed it, without the metadata
Antigravity wraps it in, each reply with the reasoning written in plain text,
each tool's arguments and output, and each compaction's summary. A turn
waiting to be sent keeps what was said in the plugin's own folder, readable by
you alone, until it goes.

The plugin's failures are lines in a log of its own, naming the session by the
start of its id, the kind of thing that went wrong and, where Telmoni refused a
turn, its answer, never anything said in the session. It never holds the
agent up: its hook hands its work to a process of its own and returns at once.

### Tags

Tags label a session's turns, so one session's runs say which repository or
branch each was about as the work moves between them. They are set two ways,
and never derived from a path:

- **A file**, `.telmoni-tags.json`, in the folder a turn started in or the
  nearest folder above it holding one: `{"repo": "telmoni", "branch": "main"}`.
  Its tags go on every turn started there. It is read for its tags alone,
  never through a link, and its path is never sent.
- **Asking**, in Claude Code: `/telmoni-observability:tag repo=telmoni`, or in
  plain words, "tag this repo telmoni", which has Claude call the plugin's
  `tag` skill. Several go at once (`repo=telmoni branch=main`), and `repo=`
  takes one back. A tag you ask for holds from that turn to the session's end,
  or until you change it or take it back, and wins over the file's for its key;
  a turn already recorded keeps what it was sent with. In Antigravity, ask the
  agent to tag the workspace and the plugin's skill writes the file.

A key is 1 to 64 letters, digits, `_`, `.` or `-`, and a value up to 256
characters; a turn carries 32 tags at most, in Claude Code `skills` among
them, which is its plugin's own. A tag that breaks a rule is dropped with a line in the plugin's
log, and the turn is sent without it. A project keeps up to 64 tag keys a UTC
day, each taking up to 500 values; past them, ingest drops the tag and keeps
the span ([its cap](/docs/api/ingest#what-is-dropped-at-the-door)). Tags are
metadata: they are sent in every content mode and seen by everyone on the
project, so no secret or personal detail belongs in one. `repo` and `branch`
are good keys to start with.

## Claude Code

Its repository is its marketplace, and the plugin is the repository itself:
Claude Code clones it with your git, and the hook runs from the clone, so
there is nothing to build. Installed so, it loads in every Claude Code you
start, an editor's included, and `claude plugin update
telmoni-observability@telmoni-plugins` takes the next version:

```sh
claude plugin marketplace add telmoni/claude-code-observability-plugin
claude plugin install telmoni-observability@telmoni-plugins
```

From a checkout, start Claude Code with the plugin and your key in its
environment instead; that one session alone loads it, as cloned:

```sh
TELMONI_API_KEY=tm_… claude --plugin-dir ./claude-code-observability-plugin
```

In a Claude Code session, set the key with
`/plugin configure telmoni-observability@telmoni-plugins`. From your shell,
`claude plugin configure telmoni-observability@telmoni-plugins --values-stdin`
takes the configuration as JSON (`{"TELMONI_API_KEY": "tm_…"}`); without
`--values-stdin` it only lists the options. Claude Code keeps the key with its
own credentials: in the Keychain on macOS, and in its credentials file
elsewhere. Left blank, the endpoint is `https://api.telmoni.com`; a self-hosted
Telmoni gives its own machine host. A `TELMONI_API_KEY` in the environment
Claude Code starts in — your shell's, or a repository's `.claude/settings.json`
`env` block — comes before the plugin's own settings, so one checkout can report
to another project, and goes with the `TELMONI_ENDPOINT` beside it there, or the
default: a key is never sent to an endpoint named somewhere else, so a
repository that names its own endpoint gets no one's machine-wide key.

Plugins load as a session starts, so start a new one once the key is set. The
hook runs when a turn stops, when an API error ends one, and when the session
ends, and hands its work to a process of its own, so no turn waits on
Telmoni; a turn that started a subagent in the background is sent once the
subagent's report or notice has been answered, and the log says so at each
hook that holds it. Its log is `hook.log` in the plugin's
data folder: `~/.claude/plugins/data/telmoni-observability-telmoni-plugins/`
for an install from the marketplace, `telmoni-observability-inline/` there
under `--plugin-dir`, or `~/.claude/telmoni/` where Claude Code gives the
plugin no data folder, each under `CLAUDE_CONFIG_DIR` where you set one.

## Antigravity

The plugin is its repository, and the `agy` CLI installs it from its address or
from a clone, copying it into
`~/.gemini/config/plugins/telmoni-observability/`; there is nothing to build.
To update, install it again: Antigravity replaces the copy it has.

```sh
agy plugin install https://github.com/telmoni/antigravity-observability-plugin
```

Antigravity gives a plugin's hooks no settings of their own, so the key goes in
one of two places. A `TELMONI_API_KEY` in the environment the CLI starts in
comes first, with the `TELMONI_ENDPOINT` beside it there; else the key file,
`~/.gemini/config/telmoni.json`, `{"apiKey": "tm_…"}`, with `"endpoint"`
beside it for a self-hosted Telmoni. The plugin reads the file only while it is
yours and shut to everyone else: one anyone else can read sends nothing, and
the log says why. Write it so the key never reaches your shell's history: run
this, type the JSON, press Enter, then Ctrl-D.

```sh
(umask 077 && cat > ~/.gemini/config/telmoni.json) && chmod 600 ~/.gemini/config/telmoni.json
```

Left blank, the endpoint is `https://api.telmoni.com`. A key is never sent to
an endpoint named somewhere else. The file is read as each turn ends, so a
change takes effect from the next turn; a key in the environment is read as the
CLI starts.

The plugin runs on Antigravity's `Stop` hook and sends a turn once the agent's
loop stops with no background task still running. The first stop it hears in
a conversation is where it starts: turns from before it was installed, or
before a key was set, stay on your machine. Antigravity's docs list a plugin's
hooks for its CLI; if the App's or the IDE's sessions don't show up, add the
plugin's hook to your global `~/.gemini/config/hooks.json`, as
[its README](https://github.com/telmoni/antigravity-observability-plugin#the-antigravity-app-and-ide)
shows; where both run, each turn is still sent once. Its log is
`~/.gemini/config/telmoni/hook.log`; if it is missing, check that
`agy plugin list` shows the plugin enabled. To remove it, run
`agy plugin uninstall telmoni-observability`, then delete the key file and
`~/.gemini/config/telmoni/`.
